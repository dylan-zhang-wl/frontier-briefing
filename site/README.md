# site/ · 每日前沿简报网页模板

> **现行模板是 v3（`site/v3/` ＋ `site/tools/make_issue_v3.py`、`build_v3.py`），见第十节；v2（`site/v2/` ＋ `site/tools/build_v2.py`，第九节）只为复现旧期保留。** 第一至八节说的是第一版模板（`site/index.html`、`app.js`、`style.css`），保留它是为了还能重建 `测试版/2026-10-31/07_网页/`。`site/video.js` 两版共用。

2026-10-31 建。一个静态网页模板：顶部"日卡"，下面先放 HTML 动画视频，再放播客播放器，最后是图文各栏、完整来源和 AI 生成说明。现在装的是样例数据（`mock/issue.js`），用来看版式。

## 一、怎么打开

- **直接双击 `index.html`** 就能看（`file://` 方式，不需要起服务器，不连外网，不依赖任何 CDN 或在线字体）。
- 页面按顺序找数据文件：先找 `site/issue.js`，没有就用 `mock/issue.js`。所以把真数据存成 `site/issue.js`，刷新页面就换过来了。找不到 `issue.js` 时控制台会报一条"文件不存在"，属于正常现象。
- 也可以在地址后面指定别的数据文件，例如：
  `index.html?issue=../测试版/2026-10-31/issue.js`
  只接受以 `.js` 结尾的相对路径（不能带 `http:`、`//` 这类前缀），防止有人用链接塞进别的网站的脚本。
- 想改默认的查找顺序，改 `index.html` 里这一行：`<meta name="fd-issue" content="issue.js mock/issue.js">`。

## 二、文件

| 文件 | 作用 |
|---|---|
| `index.html` | 页面骨架 |
| `style.css` | 全部样式：暖白纸张底、墨黑字、一个主题色（深青，与配图的暖白、墨黑、深青一致），浅色和深色两套 |
| `app.js` | 读数据、渲染整页、中英切换、播客播放器、日卡"保存为图片" |
| `video.js` | HTML 动画播放器（不是 MP4）：按时间轴切场景、逐步出元素，与旁白同步；没音频时自动"无声预览" |
| `mock/issue.js` | 样例数据，覆盖所有栏目和 7 种场景 |
| `mock/img/` | 样例配图（手写 SVG，深青色蓝晒风格占位） |
| `mock/audio/` | 样例音频：用 macOS 自带的系统语音（`say` 命令）生成的占位音，时间轴按它实测；正式版换成 Gemini／MiMo |
| `tools/build_testpage.py` | 把一期测试版（`测试版/日期/` 下的 04_文稿、05_配音、06_配图）组装成 `07_网页/`，见第八节 |

## 三、数据格式

数据文件是一段 JavaScript：`window.ISSUE = { … };`。用这种写法而不用 JSON 文件，是因为双击打开（`file://`）时浏览器不允许网页用 `fetch` 读本地文件，但允许加载 `<script>`。

约定的字段全部沿用（与 `pipeline/prompts/写稿_网页.md`、`写稿_视频.md` 的输出一致）；下面标 **补充** 的是这次加的，全部可省略，省略时页面照常显示。

### 3.1 顶层

| 字段 | 说明 |
|---|---|
| `date` | `"2026-10-30"` |
| `weekday_zh` / `weekday_en` | `"星期五"` / `"Friday"` |
| `daily_card` | 日卡，见 3.2 |
| `video` | 视频，见 3.3；没有就不显示视频区 |
| `podcast` | 播客，见 3.4；没有就不显示播客区 |
| `sections` | 图文各栏，见 3.5，按数组顺序显示 |
| `sources` | 全部来源 `[{id, name, url, date, type}]`；条目里引用了但这里没列的来源，页面会自动补进完整来源列表 |
| `disclosure_zh` / `disclosure_en` | AI 生成说明 |
| `meta` **补充** | `mock`（true 时页面顶部显示"样例数据"条）、`notice_zh/en`（样例说明文字）、`issue_no`、`edition_zh/en`（如"样刊"）、`site`（显示在日卡底部的网址）、`generated_at`（ISO 时间）、`how_zh/en`（生成方式）、`contact_zh/en`（更正与下架的联系方式） |
| `asset_base` **补充** | 图片和音频路径的前缀。不写时，**相对路径按 issue.js 所在的文件夹解析**（例如 `mock/issue.js` 里写 `img/a.svg`，实际读 `mock/img/a.svg`） |

**通用写法**
- 双语字段都是 `xxx_zh` / `xxx_en`。英文缺了就显示中文，不会空着。
- 正文（`body`、`summary`、`why` 等）支持三种小标记：`**加粗**`；`[^s1]` 引用来源 s1（显示成上标编号，点了跳到完整来源列表）；中文里的"中文（English）"会自动把英文部分排成浅一号的字，不用手动标。
- `body` 可以是一个字符串（用换行分段），也可以是字符串数组。
- 来源编号按阅读顺序自动生成：页面上第一个被引用的来源是 [1]。
- `image` 可以是路径字符串，也可以是对象：`{src, alt_zh, alt_en, caption_zh, caption_en, credit_zh, credit_en}`。

### 3.2 日卡 `daily_card`

```js
daily_card: {
  headlines: [{zh, en, ref}],          // 今日三件事；ref（补充）= 条目 id，点了跳到正文
  term: {zh, en, explain_zh, explain_en, ref},
  image: "img/card.jpg" 或 {src, alt_zh, alt_en}
}
```

"保存为图片"用 Canvas（浏览器自带的画布）重新画一张 1080 像素宽的 PNG，不依赖任何库。配图能否画进去取决于浏览器的跨源规则，见第五节。

### 3.3 视频 `video`

```js
video: {
  title_zh, title_en,                  // 补充：视频区标题（视频稿指令本来就输出）
  audio: "audio/video.mp3",            // 旁白音频；缺失或加载失败 → 自动无声预览
  duration: 87.3,                      // 秒
  poster_time: 6.0,                    // 补充：封面停在第几秒；不写就停在第一个场景全部出齐的时刻
  scenes: [...],
  subtitles: [{start, end, zh, en}]    // 字幕；不写就按每个场景的 narration_zh/en 自动切句、按字数分配时间
}
```

**场景**（`type` 共 7 种：`title | stat | compare | quote | list | image | source`）

| 字段 | 用于 | 说明 |
|---|---|---|
| `start`, `end` | 全部 | 秒。**可以不写**：页面按 `narration_zh` 的字数估算（约每秒 4.6 字），并在视频下方提示"时间是估算的"。配音、对齐之后再填真时间 |
| `heading_zh/en`, `body_zh/en` | 全部 | 大标题、一句说明 |
| `kicker_zh/en` **补充** | 全部 | 画面左上角的小标签，如"第一件 · 谷歌" |
| `label_zh/en` **补充** | 全部 | 场景列表按钮上的短名；不写就用 heading |
| `stat: {value, label_zh, label_en, value_en}` | stat | 大数字，自动从 0 滚到目标值（"65.2%""$0.0336"都行；"$2 / $10"这种含两个数字的不滚） |
| `bars: [{label, value, unit, label_en, value_en, unit_en, highlight}]` | compare | 对比条形图；`highlight: true` 的那根用主题色，不写就高亮最大值。英文版可以换单位（如 300 亿 → 30B） |
| `scale_max` **补充** | compare | 条形图的满刻度（百分比可设 100）；不写按最大值 |
| `quote: {text_zh, text_en, who, who_en}` | quote | 引语 |
| `items_zh: []`, `items_en: []` | list | 要点（视频稿指令的写法）；也接受 `items: [{zh, en}]` |
| `image` | image | 配图（对象写法可带 `credit_zh/en` 图源） |
| `source: {name, url, date}` | 全部 | 在 source 场景里显示成来源卡；在其他场景里显示成画面底部的"来源：……"一行 |
| `sources: [...]` **补充** | source | 多张来源卡（最多一行三张） |
| `steps` **补充** | 全部 | 每个元素出现的时刻（秒，绝对时间），用来和旁白里某个词对齐，见下 |
| `narration_zh/en` | 全部 | 旁白原文（视频稿指令输出）；用于自动生成字幕和估算时间 |

**`steps` 的写法**：键名就是元素名，数组表示第几根条／第几个要点／第几张卡。

```js
steps: { heading: 18.1, bars: [22.6, 24.5], body: 26.2, source: 26.9 }
```

可用的键：`heading`、`body`、`rule`（title 场景的短横线）、`stat`、`label`、`bars[]`、`items[]`、`quote`、`who`、`image`、`credit`、`cards[]`、`source`。没写的元素按顺序自动排在场景的前半段。样例里的时刻是按"这个词在这句话里的位置"估出来的；接上强制对齐（把已知文字和音频逐字对上时间）后，可以精确到词。

**画面完全由时间决定**：播放器每一帧只看"现在是第几秒"，算出每个元素该出现到什么程度。所以拖动、暂停、跳场景都不会错位；以后要导出 MP4，也只是逐个时刻截图（`FD.players.video.seek(秒)` 后截图）。

### 3.4 播客 `podcast`

```js
podcast: {
  variants: [
    {id: "gemini", label_zh: "Gemini 版", label_en: "Gemini", file: "audio/gemini.mp3",
     duration: 642.1,                          // 补充：音频没加载出来时也能显示总长
     chapters: [{start, title_zh, title_en}],  // 补充：这个版本自己的章节时间
     note_zh, note_en}                         // 补充：版本说明，显示在切换按钮下面
  ],
  chapters: [{start, title_zh, title_en}]      // 各版本共用的章节（版本自己没写 chapters 时用它）
}
```

两种配音语速不同，同一章在两个版本里的起点不一样，所以每个版本最好带自己的 `chapters`。切换版本时，如果已经听了一部分，会跳到新版本里**同一章的开头**接着放。某个版本的音频文件不存在时，播放按钮变灰并提示"这个版本的音频暂缺"，章节列表照常显示。

### 3.5 图文 `sections`

```js
sections: [{kind, title_zh?, title_en?, intro_zh?, intro_en?, items: [...]}]
```

`kind` 有 6 种：`headline`（头条）、`brief`（要闻）、`flash`（快讯）、`term`（今日一词）、`cn_intl`（中外对照）、`teaser`（预告观察）。同一种出现多次会合并成一栏。`title`、`intro`（补充）可覆盖默认的栏目名和说明。

**通用条目字段**（与写稿指令一致）：`id, title_zh/en, summary_zh/en, body_zh/en, why_zh/en, numbers, chart, image, sources, related, status`

| 字段 | 说明 |
|---|---|
| `status` | `confirmed`（已确认）、`reported`（媒体报道）、`teaser`（未经证实）；显示成徽章 |
| `numbers: [{value, label_zh, label_en, source_id}]` | 关键数字。补充：`value_en`（英文版换写法，如"6.3 万"→"63k"）、`context_zh/en`（和谁比，如"高于 Opus 5.5 的 59.6%"）、`quote`（原文逐字片段，显示成可展开的"原文片段"，方便查证） |
| `chart: {type:"bar", title_zh, title_en, unit, series:[{label, value}]}` | 手写 SVG 条形图。补充：`max`（满刻度，百分比设 100 会画出灰色底槽）、`highlight`（高亮哪一项的 label）、`unit_en`、`series[].label_en/value_en`、`note_zh/en`、`source_id`。`chart: null` 时不画 |
| `sources` | `[{id, name, url, date, type}]`，也可以只写 `[{id}]`，其余从顶层 `sources` 取。`type`：`official / media / social / paper / community` |
| `related: [{id, note_zh, note_en}]` | 同期条目之间的关系；补充：写 `url` 可以链到往期 |
| `why_zh/en` | 显示在灰底的"为什么重要 · 解读"框里，和事实分开 |
| `kicker_zh/en`、`region`（`cn`/`intl`） **补充** | 小标签、"国内／国际"标记 |
| `quote` **补充** | 头条里的原话中英对照：`{text, text_zh, who, who_en, source_id}` |

**各栏的额外字段**

- `term`（今日一词）：`title_zh`＝中文词，`title_en`＝英文词，`summary`＝大白话，`body`＝今天新闻里的用法。补充：`aliases_zh`（常见译法，第一个高亮）、`example: {en, zh}`（例句，英文里的原词自动加粗）、`note_zh/en`（译法说明）、`ask_zh/en`（留给读者的问题）。
- `cn_intl`（中外对照）：推荐一个条目里放一对：`{id, title_zh, title_en, cn: {条目字段}, intl: {条目字段}, why_zh, why_en, related}`，`why` 显示为"对照看点"。如果写稿时输出的是普通条目，页面会按顺序两两配对（`region: "cn"` 的放左边）。
- `teaser`（预告观察）：整栏顶部固定一条醒目的"未经证实"说明，每张卡左上角也有"未经证实"标签，与数据里写不写无关。补充：`post: {who, who_en, role_zh, role_en, platform, platform_en, handle, posted_at, text, text_zh, text_en}`（原帖；英文原话下面自动配中文意思）、`readings_zh/en`（几种可能的解读）、`verify_zh/en`（怎样才算证实）。
- `flash`（快讯）：只有工作日才有，由流水线决定；页面不检查星期几。某天给了 flash 但条目为空：工作日不显示这一栏，周末显示"今天是周末，快讯暂停"。

## 四、页面行为

- **中英切换**：右上角"中／EN"，默认中文。选择记在浏览器本地存储（localStorage）里，键名 `fd.lang`；读写都包了 try/catch（出错就忽略），浏览器禁用存储时照常切换，只是下次不记得。切换时停在原来读到的位置。
- **主题**：右上角半圆按钮，在"跟随系统 → 浅色 → 深色"之间切换，记在 `fd.theme`。
- **其他记住的设置**：视频字幕开关 `fd.video.cc`、播客版本 `fd.podcast.variant`、播客倍速 `fd.podcast.rate`。
- **视频**：点画面或空格键播放／暂停；←／→ 快退快进 5 秒；Shift＋←／→ 上一个／下一个场景；C 字幕，M 无声预览，F 全屏。暂停时点下面的场景按钮，会直接停在该场景"元素全部出齐"的那一刻，方便逐个检查画面。手机上画面是 4:5 竖版，电脑上是 16:9。
- **只放一个声音**：视频和播客不会同时出声，开一个，另一个自动暂停。
- **保存为图片**：按当前的语言和深浅色出图，弹窗里预览；电脑点"下载 PNG"，手机长按图片存相册；支持系统分享的设备会多一个"分享"按钮。

## 五、换成真数据

1. 流水线按第三节的格式写出 `issue.js`（`window.ISSUE = {…};`）。写稿指令输出的 JSON 基本可以直接放进去；视频场景先不带时间也能看（估算时间轴＋无声预览）。
2. 图片、音频和 `issue.js` 放在同一个文件夹（或其子文件夹），字段里写相对路径。
3. 配音完成后，把每个场景的 `start`/`end`、`subtitles`、各版本的 `chapters` 和 `duration` 填上真时间；有词级对齐时再填 `steps`。
4. 放到 `site/issue.js`，或者用 `index.html?issue=路径/issue.js` 打开。
5. 日卡配图想在"双击打开"时也能画进导出图片，就把这张图写成 data URI（把图片内容编码成一串文字直接放进字段，样例就是这么做的，约增加三分之一体积）；部署到网站后用普通路径即可。

## 六、已知限制

- 双击打开（`file://`）时，Chrome 等浏览器把每个本地文件当成不同来源，日卡配图如果是普通文件路径，就不能画进导出的 PNG（浏览器的跨源保护）。页面会自动改用纹样代替并在弹窗里说明；部署到网站、或配图用 data URI 时没有这个问题。
- 视频是网页动画，不是视频文件，不能直接下载或发到视频平台；要 MP4 需要另做逐帧截图合成（时间驱动的设计已为此留好接口）。
- 全屏在 iPhone 上不可用（iOS 只允许 `<video>` 全屏），按钮会自动隐藏；iPad 和电脑可用。
- 字体只用系统自带的（苹方、宋体、DIN 等），不同系统上字形会有差别；Windows 上数字字体退到 Bahnschrift 或 Arial。
- 样例音频是 macOS 系统语音，只用来测试同步、切换和章节跳转，音质不代表正式版。
- 视频场景的元素出现时刻，样例里是按字数估的，和旁白大致同步；精确到词要等流水线做强制对齐。
- 往期、追踪、候选池等"工作台"页面不在这次范围内。

## 七、样例数据从哪来

`mock/issue.js` 的内容取自项目里的调研文档和 `配音测试/第一轮_盲听/测试稿与指令.md`（二手材料，没有逐条核对原文），人物"示例人物 A／B"是虚构的，所有链接都是 `example.com` 占位。页面顶部有"样例"条提示。

样例是用一个一次性脚本生成的（只用 Python 标准库、macOS `say` 和 ffmpeg，没有调用任何大模型接口；脚本没有放进仓库）：逐句合成旁白、量出每句时长，再据此写出场景起止、字幕和 `steps`。真数据的时间轴应来自正式配音之后的对齐结果。

## 八、真数据测试版与模板新增的字段（2026-10-31）

`测试版/2026-10-31/07_网页/` 是用这个模板和当天真数据组装的成品，双击 `index.html` 即可看。重新组装：在项目根目录运行

```
python3 site/tools/build_testpage.py 测试版/2026-10-31
```

脚本只读 04_文稿、05_配音、06_配图，只写 `07_网页/`。它替写稿结果做了这些整理（都是格式整理，不改内容）：

- **来源去重**：写稿 JSON 里每条的来源都从 `s1` 编起，不同条目会撞号；脚本按网址合并去重，重新编号，同时改好 `numbers` 里的 `source_id`。
- **今日一词**：写稿结果里一词条目和要闻共用一个 id（如 E005），脚本把一词改成 `term`，免得页面锚点冲突；标题用日卡里的中英文词。
- **日卡三件事**：按字面相似度找到对应条目，补上 `ref`，点了能跳过去。
- **双语标签和单位**：图表标签"最初目标 / Original target""英特尔 Intel"拆成中英两份；"十亿美元"按中文习惯显示成"300 亿美元"，英文显示成"$30B"；"约 110 亿美元"在英文里显示"~$11B"。
- **视频字幕**：中文字幕由每个场景的 `narration_zh` 切句、按字数分配时间；英文没有旁白，字幕显示该场景的 `heading_en`、`body_en`。元素出现时刻能在旁白里找到对应词的就对上，找不到的按场景前半段自动排开。

### 9.1 怎么重新组装

在项目根目录 `frontier-daily/` 下运行：


- 依赖：Python 3 ＋ Pillow，ffmpeg/ffprobe（本机用 `~/.venvs/frontier-daily/bin/python` 运行）。视频 v2 第一次组装时会在本机跑一次 Whisper（`~/.venvs/digital-human/bin/mlx_whisper`，离线），之后用缓存。不调用任何模型接口。只读期目录，只写输出目录（默认 `<期目录>/08_网页v2/`）。

- 换播客：改 `site/tools/v2_issues/<日期>.py` 里的 `PODCAST_DIR`，或运行时加 `--podcast`。脚本发现 `05_配音/v2_…` 文件夹时会在最后提示一句。
- 补配图：把图放进 `06_配图/`（文件名见配置里的 `IMAGES`），重新组装即可；缺图时页面用深色网格占位，不会空着。

### 9.4 每期配置 `site/tools/v2_issues/<日期>.py`

- `WEB`、`CARDS`、`CANDIDATES`、`VIDEO_SCRIPT`、`VIDEO_AUDIO`、`PODCAST_DIR`：用哪些输入文件（本期只用 Claude 稿）。
- `IMAGES`：`06_配图` 下的图配给谁（card、E001…、term），以及中英文替代文字（读屏软件念的说明）。
- `NUMBERS`：今日数字 3–5 个。
- `CHARTS`：图表。`type` 有 `dumbbell`（哑铃图：前后对比）、`timeline`（时间线）、`graph`（关系图）、`bars`（横条图）、`steps`（阶梯折线）。`STORY_CHARTS` 指定放进哪条头条（多张时出现小标签切换），`FLASH_CHART` 放在快讯旁边。
- `WATCH`：预告看板。`status` 取 `rumor` 传闻、`teaser` 预告（当事方自己说的）、`scheduled` 已排期（有明确日期）、`reported` 报道称。超过 6 条自动分页。
- `PAIRS`：国内外对照的配对和标签；中间的关系说明取自稿件里这两条之间的 `related` 说明。

**核对规则（程序把关）**：配置里每个数字、每条预告都写 `ref=(事件号, "F3" 或 "N2", 核对片段)`，指向 `cards_写稿用.json` 里该事件的第几条事实（facts）或数字（numbers）。核对片段必须原样出现在那一条里，否则组装报错停下。出处编号由脚本按那一条的来源自动换算。这样图表、今日数字、预告看板只能用核对过、带出处的数字和事实。

### 9.5 脚本替稿件做的整理

- **上标引用**：Claude 稿正文没有引用标记。脚本把每句话和这条事件卡里的事实、数字按字面相似度对上，用最像的那条事实的出处；“我们的理解是……”这类解读句不挂；同一出处连着几句时只在最后一句后标一次。
- **三句话**：每段第一句，不足三句按顺序补；“读全文”展开完整正文。
- **报道光谱**：`candidates.json` 里归并到这个事件的条目，按媒体去重，分中文、英文、社区/社交三类计数，鼠标停上去看名单。
- **听这一段**：头条用“热点一／热点二”章节起点；其他条目在对应章节里找最像的一段，按 `qc.json` 里分块的起止时间和字数比例估算（可能差几秒）。混了片头曲、转场音的播客，其 `qc.json` 只有“时间线”，脚本会顺着其中的“人声来源”找到纯人声版的分块，再平移到混音后的时间。
- **看这一段**：视频 v2 每一屏都带事件号，条目跳到这条事件最早出现的那一屏（本期旁白只讲了 E001、E004、E008：OpenAI 0:00、英特尔 0:34、Meta 0:43）；旁白没讲的头条显示“视频未涉及”。第一版视频仍按标题相似度归属。
- 播客码率高于 80 kbps 时转成单声道 64 kbps（本期约 6 MB）。

### 9.6 页面行为

- 顶栏：品牌名、“测试版”小标、日期（前一期／后一期／日历，日历里只有出过简报的日子能点）、中／EN、深浅色（跟随系统 → 浅色 → 深色）。记住的设置：`fd.lang`、`fd.theme`、`fd.pod.rate`、`fd.video.cc`（存在浏览器本地，禁用存储时照常用，只是下次不记得）。

- 参考来源默认折叠；展开后先列被引用次数最多的 5 条，可展开全部（按编号排）。
- 头条：鼠标划过或点击标签切换，手机上点标签或左右滑。“听这一段”让播客跳到对应时间播放，播放器滚出视野后底部出现迷你播放条；“看这一段”滚到视频并从对应场景播放。视频和播客不会同时出声。

### 9.8 视频 v2：GSAP 动画 · 逐字对齐 · 场景模板库（2026-10-31）

第一版每一屏都是“大字加一个数字”。v2 把 8 个场景拆成更细的“节拍”（一屏一个，本期 13 屏），每屏按内容自动挑一种动画模板，画面元素在旁白说到对应词的那一刻出现。旁白音频不变，不重新配音。

**流程**（都在 `build_v2.py` 里自动完成，不调用任何模型接口）

1. **逐字对齐**（`site/tools/video_align.py`）：本机 Whisper（`mlx_whisper`，模型 whisper-large-v3-turbo，离线 `HF_HUB_OFFLINE=1`，`--word-timestamps True --language zh`）给出每个词的时间。转写会把“三百亿”写成“300亿”，还可能有错字，所以先把转写里的数字换成汉字读法（300 → 三百，28.58% → 百分之二十八点五八），再和视频稿逐字比对：比上的字用转写时间，没比上的按前后插值。接着用 ffmpeg 的静音检测找“停顿后重新开口”的时刻：整体偏早或偏晚就整体平移；每个停顿后的第一个字吸附到实测时刻；场景的第一个字不早于配音分块的起点（配音目录的 `chapters.json`）。
   转写结果缓存在 `issues/<日期>/video/whisper_words.json`，里面记着音频的内容指纹（sha1），音频变了会自动重跑。配音目录里如果有 `words.json`（同样格式），脚本优先用它。
2. **场景计划**（`site/tools/video_plan.py`）：读节拍表，把触发词换成秒，按内容挑模板，核对数字，并按 ref 指向的出处自动写每屏底部的“来源”一行。
3. **播放**（`site/v2/video2.js`）：所有动画放进一条暂停的 GSAP 时间轴，每一帧只做 `tl.time(音频当前秒)`。画面完全由时间决定，所以播放、拖动、暂停、跳场景都不会错位；以后要导出 MP4，逐个时刻截图即可。

**本期同步精度**：稿子 343 个字全部比上；Whisper 整体偏早 0.16 秒，已平移。停顿后开口处，平移后的 Whisper 时间与实测相差：中位 0.10 秒，九成在 0.23 秒内，最大 0.5 秒；这 22 处已改用实测时刻。句中其他字仍用 Whisper 时间，误差约 ±0.1 秒。
浏览器实测：播放时画面时间与音频时间相差不超过 0.02 秒；76 个画面元素在对应词前 0.15 秒都还看不见，说到后 0.75 秒内都已完全显出；24 段字幕的逐字变亮全部对上。

**模板库（12 种）与“内容形状”**

| 模板 | 画面 | 用于形状 `shape` | 本期用在 |
|---|---|---|---|
| `kinetic` 动态标题 | 词按旁白逐个从下方顶出，数字等宽放大，旧数字可被划掉 | hook（开场）、points 的备选 | 开场“300 亿→200 亿？”；“接下来看两点” |
| `kenburns` 配图缓推 | 配图慢慢推近，前景标签反向平移形成视差 | image | 据《金融时报》（E001 配图） |
| `dumbbell` 哑铃图 | 之前的点先出现，之后的点沿刻度滑过去，差值条拉开 | change（前后对比） | 融资 300 → 约 200 亿 |
| `bars` 条形图生长 | 各条按旁白生长、数值滚动，可加参考线 | amounts（几项数值） | 300 / 200 / 已获承诺约 110，加“目标的一半”线 |
| `split` 左右分屏 | 左块出现、箭头画过去、右块的数从左块的值滚到新值 | change 的备选、contrast | 估值 1.4 → 1.25 万亿 |
| `quote` 引语逐字高亮 | 引语里的字随旁白逐字变亮，下附原文措辞 | quote | “收敛野心”（tempers its ambitions） |
| `graph` 关系图生长 | 节点按旁白出现，连线逐条画出，关键连线流动 | relation | AI 股票抛售 → 部分投资者 → 削减承诺 → OpenAI |
| `counter` 数字滚动 | 从 0 滚到实际值，涨跌箭头落下，落定时闪一下 | number | 英特尔 −28.58% |
| `timeline` 时间线推进 | 游标沿年代刻度走到每个日子，事件依次亮出 | dates | 1974 年 −29.9%（最大）→ 10 月 30 日 −28.58%（第二大） |
| `cascade` 要点落下 | 要点一条条从上方落入 | points | 标普：展望转负面 / 理由 / 评级仍为 AA- |
| `glitch` 不确定 | 轻微故障（错位、色散、扫描线）＋“未确认”印章 | uncertain | 全部来自匿名消息源 · 官方尚未确认 |
| `recap` 回顾宫格＋来源 | 每条一块（点了跳到网页对应条目），提示完整来源在下方 | recap | 结尾 |

挑模板的规则：同一模板不连用；`hook`、`change`、`points` 这三种形状的候选同样合适，优先用本期还没用过的，都用过就挑最久没用的；其余形状一律用最合适的第一个，只有和上一屏相同时才退到第二个。节拍里写 `tpl` 可以强制指定。相邻两屏模板相同时组装报错；全期少于 6 种时给出提示。

**节拍表的写法**（每期配置 `site/tools/v2_issues/<日期>.py` 的 `VIDEO_BEATS`，或配置里 `VIDEO_BEATS_FILE` 指向的同结构 JSON）

| 键 | 含义 |
|---|---|
| `at` | 这一屏从旁白的哪几个字开始（忽略标点空格，按顺序往后找）。一屏比这几个字早 0.22 秒切入 |
| `shape` | 内容形状，见上表；程序据此挑模板 |
| `ev` | 事件号：用于“看这一段”和回顾宫格的跳转 |
| `chip`、`kicker` | 场景小标签、画面左上角小标题，都写 `(中文, 英文)` |
| `sub_en` | 英文界面的字幕（这一屏旁白的英文大意） |
| 各形状的内容 | hook：`lines`（每行若干词）；image：`image`、`tags`、`title`；change：`frm`、`to`、`delta`、`max`、`ticks`；amounts：`items`、`marker`；number：`pre`、`name`、`label`、`value`（`to`、`dec`、`pre`、`suf`、`dir`）；quote：`quote`（`sync` 为旁白里对应的那几个字，用来逐字高亮）、`who`；relation：`nodes`（`x`、`y` 为百分比位置）、`links`（`n1` → `n2`，`flow` 表示流动）；dates：`span`、`ticks`、`items`（`at` 为年份）；points：`title`、`items`；uncertain：`small`、`big`、`stamp`；recap：`tiles`、`cta` |
| `cue` | 元素在旁白说到哪几个字时出现（比那个字早 0.08 秒开始动，说到时正好显出）；不写就在这一屏开头依次出现；`strike` 是划掉旧数字的时刻 |
| `ref` / `refs` | `(事件号, "N0"/"F2"/"Q3", 核对片段)`。凡是带数字的文字必须写，否则组装报错。Q 指事件卡 `open_questions_zh` 的第几条（如“全部依赖匿名消息源”）。核对规则同 9.4 |

**数据格式**

- `issue.js` 的 `media.video`：`{v: 2, title_zh/en, audio, duration, beats: [...], cues: [...], templates, auto_plan, numbers_checked, sync}`。
  - `beats[i]`：`{i, tpl, shape, ev, start, end, label_zh/en, kicker_zh/en, sub_en, src_zh/en, …各模板的内容}`。每个元素带 `t`（出现的秒）和 `t_end`（触发词说完的秒）；引语另带 `ct`（每个字的秒）；被划掉的数字带 `strike_t`；带数字的元素带 `cite`（全站来源编号）。
  - `cues[i]`：`{start, end, text, t: [每个字的起始秒]}`。字幕按句切，长句按逗号再切成约 18 字以内的一段。
- `issues/<日期>/video/align.json`：`units`（稿子里每个字的起止秒）、`sentences`（每句）、`cues`（每段字幕）、`keywords`（每个触发词的秒）、`scenes`（8 个原场景的起止）、`accuracy`（精度自检）。
- `issues/<日期>/video/plan.json`：模板库说明，以及与 `media.video` 相同的场景计划（不含字幕），方便检查。

**以后每天怎么自动生成场景计划**

1. 写视频稿那一步（流水线）让模型在输出原来 8 个场景的同时，按上表输出节拍表 JSON（如 `04_文稿/claude_视频_节拍.json`）。模型只提内容、形状、触发词和 ref，不写时间，也不选模板；每期配置写 `VIDEO_BEATS_FILE = "04_文稿/claude_视频_节拍.json"`。程序会把关：触发词必须能在旁白里按顺序找到，带数字的元素必须有核对得上的 ref，不合格就报错停下，不会带着编造的数字上线。
2. 配音那一步已经在用 Whisper 对稿，顺手把逐词时间存成配音目录里的 `words.json`（`{audio_sha1, words: [{w, s, e}]}`）。这样组装时不必再跑 Whisper。
3. 组装命令不变：`build_v2.py <期目录> [--podcast …]`。对齐、换算时间、挑模板、写来源行、接“看这一段”都由程序完成。
4. 当天没有节拍表时，程序从视频稿自动拆：长场景先放一屏配图（`kenburns`），再按场景类型选模板（title → kinetic，compare → dumbbell/bars，stat → counter，quote → quote，list → cascade，source → recap）。拿 10-31 的稿子试过：9 屏、7 种模板，能看但比较粗；而且数字没有逐条核对，组装时会提示“数字未逐条核对”。

**其他行为**

- 播放控制与第一版相同：播放暂停、拖动、上一屏下一屏、场景小标签跳转、字幕开关（记在 `fd.video.cc`）、静音预览、全屏。没有全屏接口时（如 iPhone）退成“放大铺满窗口”，按 Esc 或再点一次还原。键盘：空格、←/→ 快退快进 5 秒、Shift+←/→ 换屏、C 字幕、M 静音、F 全屏。

**已知限制**

- 句中字的时间直接用 Whisper 的，误差在 0.1 秒左右；只有停顿处吸附到了实测时刻。

### 10.6 v3.1 改了什么（10-31 晚，按用户看完 v3 的意见）
