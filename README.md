# frontier-daily · 每日AI科技前沿简报

每天自动出一期全球 AI 和科技商业前沿简报：中英双语网页、中文播客、网页里的动画视频，发到 **https://wenlongzhang.com/frontier/**。

英文名 Daily AI & Tech Frontier Briefing，简称 Frontier Briefing。读者是在英国做翻译研究的中国高校教师；内容以 AI 为主、科技商业为辅。

> 给来改这个仓库的 agent：先读 [`AGENTS.md`](AGENTS.md)（工作守则），再读本页。

几个词：
- **云端电脑**：GitHub Actions，GitHub 每次临时开一台 Linux 电脑跑流程，跑完就清掉。
- **fd**：根目录那条"一键出刊"命令，一期 17 步，做过的步骤自动跳过，停在哪就从哪接着跑。
- **claude -p**：在命令行里直接调 Claude，不开窗口，用的是用户的 Claude 订阅。
- **事件卡**：把一条新闻整理成的卡片，每条事实、数字、原话都附原文里逐字抄来的一段。后面的稿子、网页、视频只许从事件卡取事实。
- **审片**：成品出来后，另一个只读的 Claude 按清单逐项挑毛病。**放行**：审片和程序检查都过了，才自动发布。

## 一、一期有什么

| 版别 | 哪天 | 播客 | 视频 |
|---|---|---|---|
| 工作日版 | 周一到周五 | Shirley 一人，10–15 分钟 | 不超过 3 分钟，Shirley 旁白 |
| 周日深谈版 | 周日 | Shirley、Dylan 双人深谈一周持续热的一件事，15–17 分钟，覆盖周五、周六 | 不超过 3 分钟，只讲深谈那一题 |
| 周六 | 不出刊 | 只跑抓取、归并、入库 | — |

- 周六停刊从 2026-11-14 起：云端流程遇到周六的正式运行只跑第 1–3 步；`fd` 程序里按星期选版别的几处还没改（待核，见 `文档/经验/问题与解决办法.md` 第五部分）。周六"快讯＋单人深度"的写法留着，以后恢复时用。
- 网页里的视频不是 MP4，是浏览器里的三维播放器加旁白音频。
- 网址：`/frontier/` 是最新一期，`/frontier/past/` 是往期目录，`/frontier/?date=2026-11-09` 是某一期（`/frontier/2026-11-09/` 会跳过去）。默认不设口令，加 noindex（告诉搜索引擎不要收录），所以是"谁拿到网址都能打开，但搜不到"；11-10 起你可以在设置页 `/frontier/_access` 把网站切成"凭口令"（要输访问口令）或"只有我"（别人只看到"测试中"），状态存在 Cloudflare 的数据库里，每天自动发布不会改回去（`cloud/deploy/README.md`"开放程度"）。

## 二、每天怎么运转

```
 62 个来源
    │ 1 抓取 → 2 粗筛归并 → 3 记进往期事件库                    程序，不用模型
    ▼
 4 选题 → 5 事件卡（逐字核对）→ 6 写稿（播客／网页／视频分镜）
    │ 7 稿子检查 → 8 独立审读 → 9 改稿                         花钱（配音）之前的把关
    ▼
 10 配图 → 11 配音 → 12 混音 → 13 网页 → 14 视频（Claude 导演）→ 15 网页带视频
    │ 16 验收 → 17 本期报告
    ▼
 审片 → 放行判定（9 条）──过了──▶ 发布到 wenlongzhang.com/frontier
                          └没过──▶ 不发布，网站继续显示上一期，发邮件
```

| 步 | 做什么 | 用什么 |
|---|---|---|
| 1 抓取 | 把 62 个来源窗口内的新条目抓下来（订阅源、Hugging Face、Hacker News、GitHub、AINews） | `pipeline/fetch.py`，来源表 `pipeline/sources_test.yaml`；不用模型、不登录 |
| 2 粗筛、归并 | 去掉不相关的，把同一件事的几篇报道并成一个"事件"，取热度前 60 | 关键词和实体表；LaBSE 句向量（把中英文意思相近的标题算得接近） |
| 3 事件库入库 | 记进往期事件库，供跨天去重、周末汇总 | `pipeline/event_db.py` |
| 4 选题 | 定今天讲哪几件、主线、今日一词，补前一天、避开前几天讲过的 | Claude Opus 写稿子代理，按 `pipeline/prompts/选题.md`；程序再自查 |
| 5 事件卡 | 从原文摘事实、数字、原话，程序逐字核对，核不上的条目删掉 | MiMo `mimo-v2.6-pro` ＋ `pipeline/run_mimo.py` |
| 6 写稿 | 播客稿、网页稿、视频分镜（含旁白） | 同一个写稿子代理，按 `写作指南.md` 和当天版别的写稿说明 |
| 7 稿子检查 | 读音、英文名、数字、周末规则、时长、今日一词重复、分镜格式 | 程序（`lexicon_check.py`、`script_check`、`term_history.py` 等），约 2 秒 |
| 8 独立审读 | 配音前最后一道事实把关，只读，写 `审读意见.md` | 另一个 Claude Opus 子代理 |
| 9 改稿 | 按审读意见逐条改，写 `审读处理.md`，再跑一遍第 7 步 | 写稿子代理 |
| 10 配图 | 网页图和视频要新画的图 | Codex（ChatGPT 订阅）：正式运行先由 `cloud/web_images.py`（网页图）、`site/tools/video3_images.py`（视频图）画；画不成的退回网页原图、原文截图和程序画的主题色封面。`fd` 第 10–17 步带着 `--skip-images`，意思是缺图不停、用封面补 |
| 11 配音 | 播客和视频旁白配音，转写对稿、音色比对、音高语速时长把关 | Gemini `gemini-3.8-flash-tts`（Vertex）；转写用 Whisper，音色用 SpeechBrain |
| 12 混音 | 人声配底乐、片头片尾，整集响度 −16 LUFS | ffmpeg，声音包在 `pipeline/assets/music/` |
| 13 网页组装 | 生成当期网页；页面上每个数字都要在事件卡里找得到 | `site/tools/make_issue_v3.py`、`build_v3.py` |
| 14 视频 | 截原文截图 → 按第 6 步分镜组装"老路"版保底 → Claude 导演写旁白、镜头表和分镜（旁白过了第 7 步那套检查才重配视频旁白，不过就用第 6 步的旁白）、看关键帧改一轮 → 出成片；导演失败或超过 45 分钟（MiMo 备用声音重配旁白时 65 分钟）就用老路版 | `site/tools/video3_build.py`、`video3_director.py`；Playwright 和 Chrome |
| 15 网页带视频 | 把视频接进网页；视频没成就不放视频 | `build_v3.py` |
| 16 验收 | 浅色、深色、手机三种视图截图检查；上标不掉行；"听这一段"跳对位置 | `shoot_v3.js`、`check_cites.js`、`check_listen.js` |
| 17 本期报告 | 写 `00_调度报告.md`、`花费.json`，记进月度账本；在 `自检.md` 末尾补"第 10–17 步实际结果"（自检.md 是第 9 步写的） | 程序 |

每一步出错怎么办（重试、退回、停下）见 `cloud/云端全流程_2026-11-08.md` 第三节；`fd` 每步怎么判过没过见 `文档/方案/总调度说明.md`。

**审片**：第 17 步之后紧接着跑，另一个只读的 `claude -p` 按 `文档/方案/每日审片.md` 和经验库第四部分的每日审片清单逐项查，写给人看的 `审片.md` 和程序读的 `审片结论.json`。转写对不上原稿的地方写"请你耳听"，不挡发布；标"立即"的项有一项不过就不放行。

**放行**（`cloud/release/gate.py`，结果写进 `放行结论.json`）9 条全满足才发：17 步做完（配图退回程序封面不算失败）；验收过了；播客和视频旁白都配成了；没有因为出错换备用声音（因为月上限换的照常放行）；网页没用宽松模式；版别和星期几对得上；视频不超过 180 秒、播客时长在区间里；这一期、这个月花费没超；审片放行、"立即"一栏为空。

## 四、云端怎么跑

**两个仓库（2026-11 起）**：这个公开仓库 `dylan-zhang-wl/frontier-briefing` 只放程序，每天的制作（认领、第 1–17 步、审片、放行判定）在这里跑；每期内容（`测试版/`）、音乐、往期存档（`site-archive` 分支）、每次运行的整期文件包、Codex 画图（流程"配图"）、发布和发邮件（流程"放行发布"）、读者反馈都在私有仓库 `dylan-zhang-wl/frontier-daily`。公开流程开头用 `STATE_REPO_TOKEN` 从私有仓库取 `测试版/` 和音乐，结尾把同一批文字提交回私有仓库、叫私有仓库的"放行发布"；公开的运行日志和摘要只印状态，不印稿子、审片、调度报告的内容。

**手动触发**：GitHub 仓库 `dylan-zhang-wl/frontier-briefing` → Actions → 左边选 **frontier-daily** → Run workflow。下表按 `.github/workflows/frontier-daily.yml` 现行版本写；输入有变化时，以文件里每个输入的说明为准。

| 输入 | 怎么填 |
|---|---|
| `date` | 哪一期，`YYYY-MM-DD`；留空＝今天（UTC）。不能填仓库 `测试版/` 里已有的日期，否则程序会把拷来的往期文字当成"已经做过" |
| `until` | 跑到第几步：`3` 只抓取、归并、入库；`9` 到改稿；`17` 全部，之后审片、放行 |
| `from_run` | 从哪次运行的文件包接着跑：填运行编号（运行网址 `actions/runs/` 后面那串数字；文件包在私有仓库发行版 `run-<编号>`，留 14 天）；留空＝从头跑 |
| `from_step` | 接着跑时从第几步开始（4–17），只在填了 `from_run` 时有用；填 10–17 时这一步一定重做（11-09 加，不然上次做完的会被跳过），后面几步按需重做 |
| `review` | 开：第 14 步视频导演和第 17 步后的审片都用 Claude 订阅；关：导演退回老路、不审片 |
| `upload_media` | 另传一份带音频、视频的整期目录（私有仓库发行版里的 `media-<日期>.tar.gz`） |
| `test_mode` | 开：不发布、邮件只打印、配图和导演新要的图各最多画 1 张、和别的运行不排队；正式运行要关 |
| `gemini` | `off` 不用 Gemini，用 MiMo 备用声音、预算 0；`trial` 只试配一句验证身份；`default` 正式，每期 $0.6、每月 $8 |
| `extra` | 只剩 `none`（试画一张挪到私有仓库的"配图"，mode 选 trial；测试邮件挪到私有仓库的"放行发布"，勾 test_mail） |

**定时**：每天 4 个触发时刻（UTC）：主力是 Cloudflare 上的保底触发器（`cloud/trigger/`）04:17，它再在 04:43、06:47（晚补）各叫一次；GitHub 自己的定时（04:17、05:11）11-10 实测从没准点触发过（`gh run list --event schedule` 是空的），2026-11 拆仓库时先不写进公开仓库的流程文件（切换前公开仓库就建好了，定时要是来了会和旧仓库同时出刊），切换稳定以后要加回再说。保底触发器按正式的输入叫，一律按正式走：Gemini 主声音、Codex 画图、视频导演和审片都开（导演不新画图）、邮件真发、跨天状态提交回私有仓库的 main，发布看私有仓库的 `SITE_DEPLOY_ENABLED`。
- **同一天只出一期**：流程第一段 `claim` 往仓库推标签 `issue/<日期>` 认领这一天，推上去的那次才出刊，其余一分钟左右跳过（显示 skipped，不算失败、不发邮件）。测试运行和接着跑不认领。
- **出错再试**：第 4 步以前出错（还没用 Claude、没花钱）自动删掉标签，下一个时刻再试；第 4 步以后出错标签留着、发邮件，由人处理（邮件里写接着跑和删标签重跑的命令）。
- **周六**（11-14 起）：正式运行自动只跑第 1–3 步，状态照样提交回 main，出错才发邮件。
- 同一时间只跑一个正式运行或手动放行，不会两期抢着配音。详见 `cloud/云端全流程_2026-11-08.md` 第一节。

**发布开关**：私有仓库的仓库变量 `SITE_DEPLOY_ENABLED` 为 `true`、而且不是测试运行，才真的发布；否则只打包、跑 `wrangler deploy --dry-run` 检查。打开、关上的命令见私有仓库的 `cloud/密钥与重置手册.md`"仓库变量"一节。11-09 19:23 UTC 起开着。

**手动放行**：没自动放行的那期，看过觉得能发，到私有仓库的 Actions → **放行发布** → Run workflow，填日期（可选填理由，`run_id` 留空）→ Run。它从私有仓库发行版里找那天最新的整期文件包，照样逐条判一遍写进结论，然后发布、存进往期。文件包留 14 天，过了就发不了，要重跑。

**读者反馈**（11-09 晚加）：网页底部"往期"旁边有"反馈"，点开在左边弹出小框（手机上从底部升起），写哪里不对，可选填称呼和位置（正在听播客、看视频时自动带上时间点）。提交后网站程序（`cloud/deploy/src/index.js`）转交 GitHub，`读者反馈`流程（`.github/workflows/feedback.yml`）建一条 Issue（标签"反馈"），再让只读的 Claude 初看一遍，写评论、标"属实／不属实／待你看"。后台就是仓库的 Issues 页按"反馈"筛选；周六维护时处理。令牌和停用办法见 `cloud/feedback/README.md`。

**访问统计**（11-10 加，照期刊网站）：网站程序匿名记下每次打开页面、每期的“开始听”（播客）和“开始看”（视频旁白），不记 IP、不记爬虫和你自己，存在 Cloudflare 的免费数据库 `frontier-visits`；只有你（带站长 Cookie 的浏览器）能打开 https://wenlongzhang.com/frontier/_visits ，钥匙怎么设（手动流程 `.github/workflows/stats-setup.yml`）、记什么不记什么、怎么停用见 `cloud/deploy/README.md`“访问统计”一节。

**开放程度**（11-10 加）：同一把站长钥匙登录过的浏览器打开 https://wenlongzhang.com/frontier/_access ，三个大按钮切"公开／凭口令／只有我"，"凭口令"要先设访问口令；改动最多 15 秒内生效，你自己任何一档都照常看。操作步骤、已知限制见 `cloud/deploy/README.md`"开放程度"一节。

**出错邮件**：有事才发（11-10 改，原来是有备注就发）。正常发布、没有别的事、"请你耳听"全是"多半转写听错"或"拿不准"的日子不发信：
1. 没出刊：写卡在第几步、`00_调度报告.md` 开头；
2. 没放行：写没满足哪几条、`审片.md` 开头、怎么手动放行；
3. 放行了但发布出错，或者发布开关没开；
4. 发了但有事：备用声音、配图退回封面、Codex 要重新登录、Codex 额度用完（11-14 加），或者有审片判断"多半真念错"的"请你耳听"。

审片给每一处"请你耳听"写一个"判断"（`多半真念错`、`多半转写听错`，或 11-14 加的 `拿不准`：英文名拼法、语速）和一句依据，怎么判见 `文档/方案/每日审片.md` B2 步（11-14 起同音字按不带声调的拼音比，`pipeline/listen_pinyin.py`）。邮件里只列多半真念错的那几处，按时间排（先视频、后播客），关乎事实的（数字、版本号、公司名、模型名、人名）行首加【事实】；末尾一行写"另有 N 处多半是转写听错、M 处拿不准，记在这一期的 审片.md（仓库 测试版/<日期>/审片.md）"。旧格式没写判断、写的认不出，当多半真念错照发。分拣只管发不发邮件，"请你耳听"照旧不挡放行。哪些要告诉你由 `cloud/release/gate.py` 的 `split_notes` 定，放行结论的"给人看"和邮件用同一个判断。

**存在哪**：
- 发布了的期：网页文件存进本仓库的 `site-archive` 分支（`cloud/deploy/archive.py`），网站每次发布都带上全部往期。
- 跨天状态（往期事件库、月度账本、每期的选题、事件卡、网页稿、播客稿）：正式运行时提交回私有仓库的 `测试版/`（流程文件"提交跨天状态"那一步）；测试运行只作为文件包 `state-<日期>.tar.gz` 保留。
- 每期的文字记录（11-10 加）：`测试版/<日期>/` 根上的 `审片.md`、`审片结论.json`、`放行结论.json`、`00_调度报告.md`、`自检.md`、`审读意见.md`、`审读处理.md`、`花费.json`，在同一步一起提交回仓库，一期合计约 65 KB；文件不在就跳过，测试运行不提交。周六维护时直接在仓库里看这一周每期 `审片.md` 的"请你耳听"，不用再赶在产物和成品库 7 天过期以前。
- 每次运行的整期文件包（2026-11 起不再上传成产物，公开仓库的产物谁都能下载）：私有仓库的发行版 `run-<运行编号>`（草稿，只有你看得到）里的 `issue-<日期>.tar.gz`（网页、日志、文稿、审片、报告、花费）、`media-<日期>.tar.gz`（带音频、视频，没放行或测试时才有）、`state-<日期>.tar.gz`（事件库、账本），留 14 天，"放行发布"流程清理。

## 五、本机怎么跑

仓库在本机的位置：你克隆到哪里都行（下文叫“仓库根目录”）。命令都在仓库根目录运行。Python 环境是 `~/.venvs/frontier-daily`（uv 建的，`fd` 有它就自动换进去；环境和缓存都在 iCloud 外面）。

**看成品**：`python3 cloud/取回成品.py`（默认今天 UTC，`--date` 选别的一天）把云端那期取回本机 `本机资料/成品/<日期>/`（`本机资料/` 留在私有仓库那份本机副本里时，设环境变量 `FD_LOCAL_DATA=<那份>/本机资料`），双击 `10_网页v3/index.html` 就能看；mini 上每天约 08:30 自动运行。满 7 天、已经发布到网站的期会被移进废纸篓，没发布的不动；`--dry-run` 只列不动。

| 想做什么 | 命令 |
|---|---|
| 体检：软件、登录、密钥在不在（只查不改，不显示密钥） | `./fd doctor` |
| 先看计划和估计花费，不动任何文件 | `./fd run --date 2026-11-09 --dry-run` |
| 跑一期 | `./fd run --date 2026-11-09` |
| 看每一步的状态和原因 | `./fd status --date 2026-11-09` |

`fd run` 常用选项：`--until 视频`（跑到某步；步骤可写编号、英文键或中文名）、`--from 网页`、`--redo web,video`（强制重做）、`--issue-dir 目录`（指向副本，测试时用）、`--budget-usd 0.6`、`--offline`、`--skip-images`、`--use-backup`（直接用 MiMo 备用声音）、`--no-preview`、`--lenient`（网页数字核不上时去掉那几项，这一期就不会自动放行）。全部选项见 `文档/方案/总调度说明.md` 第一节。

**开关**（`fd_开关.json`，改冒号后面引号里的字，写"开"或"关"）：
- `新动效和原文截图`：关掉就不截原文截图，视频退回旧画法。
- `视频导演`：关掉就只走老路，视频和加这个开关以前逐像素一样。
- `视频旁白归导演`（11-09 加，默认开）：视频导演开着时，视频旁白也由导演写；过了第 7 步那套检查才重配视频旁白，不过就整段用第 6 步写、第 11 步配好的旁白。关掉就是导演只管画面、旁白不动。视频导演关着时它不起作用。
- `视频中文整词换行`（11-09 晚加，默认开）：视频卡片、标题、字幕按整词换行，和网页同一套（`zh_breaks.py`）；只在显示那一层加看不见的换行点，触发词、字幕逐字高亮的时间不动。关掉就和加开关以前逐像素一样。
- 只管一次的话，在命令前加环境变量，比文件优先：`FD_MOTION=off ./fd run …`、`FD_DIRECTOR=off ./fd run …`、`FD_DIRECTOR_NARRATION=off ./fd run …`、`FD_VIDEO_ZH_WRAP=off ./fd run …`。

**测试**（不花钱）：
```bash
export PYTHONDONTWRITEBYTECODE=1                                # 仓库在 iCloud 里：跑测试不生成 __pycache__
PY=~/.venvs/frontier-daily/bin/python
$PY -m unittest pipeline/test_fd_motion.py                     # pipeline/ 下还有 test_lexicon_check、test_spoken_numbers 等
$PY site/tools/test_video3_director.py                          # site/tools/ 下 test_*.py 同理
python3 -m unittest discover -s cloud/release/tests -v          # 放行、邮件
python3 -m unittest discover -s cloud/deploy/tests -v           # 上线包、往期存档
python3 -m unittest discover -s cloud/trigger/tests -v          # 认领（同一天只出一期）
python3 -m unittest discover -s cloud/tests -v                  # 本机取回成品（cloud/取回成品.py）、Codex 登录失效、额度用完判定（cloud/codex_login_check.py）
cd cloud/deploy && node --test tests/worker.test.js             # 网站 Worker
cd cloud/trigger && node --test tests/worker.test.js            # 保底触发器 Worker
```
仓库里的 `测试版/` 只有跨天要用的文字，没有音频、视频、图片。完整样期（mini 试运行那周各期，含冻结的 10-31、11-01）在本机 `本机资料/归档/mini试运行_1031-1109/<日期>/`（不进 git）：整期留着的是 10-31、11-01（冻结）和 11-03、11-04、11-06（回归要整期重新组装）；11-02、11-07、11-08、11-09 在 11-09 晚瘦身，只留文字记录（音频、图片、视频移进了废纸篓，网页已在网站和 `site-archive` 分支）；做逐像素回归先复制到缓存里做副本。读完整样期的几个测试（`test_lexicon_check` 的 11-06、`test_video3_storyboard` 的 11-06、`test_v3_edge.py`、`test_listen_jump.py`）会自动找那里，也可以用环境变量 `FD_SAMPLE_ROOT` 指别处；都没有就跳过，写明原因。公开仓库里没有 `测试版/`、音乐（`pipeline/assets/music/`）和旧期数据（`site/tools/v3_issues/`、`site/tools/fixtures/`、`site/mock/`），都在私有仓库：要跑全部测试，先把私有仓库里的音乐、旧期数据（连同 `测试版/`）拷进来再跑（不提交，`.gitignore` 已经挡掉）。不拷的话，要声音包的几项会失败（`test_fd_motion.py` 第 7 步 3 项、`test_spoken_numbers.py` 1 项、`test_video3_director.py` 4 项、`test_video3_storyboard.py` 3 项），要旧期数据的 `test_v3_edge.py`、`test_listen_jump.py`、`test_make_issue.py` 会打印"跳过"。
