## 这是什么

这个仓库（`dylan-zhang-wl/frontier-daily`）从 11-08 晚起是项目的权威版本。11-09 晚起本机副本放在 iCloud 里（两台 Mac 共用，不同时操作）。它下面的 `本机资料/` 写进了 `.gitignore`，不上传 GitHub、只靠 iCloud 同步：`本机资料/成品/<日期>/` 是成品库（`取回成品.py` 每天把云端那期拼成完整的期目录放进去），`试验/` 放本机试跑和对比，`归档/` 放 mini 试运行那周各期和 11-08 前的旧代码、旧文档，说明见 `本机资料/README.md`。

`cloud/` 放的是"搬上云"另加的东西；其余目录和 mini 上的项目一样（包括中文目录名），程序里的相对路径没改。

## 怎么触发

- **定时**：主力是 Cloudflare 上的保底触发器（`trigger/`，Worker `frontier-daily-trigger`，没有网址）每天 04:17 UTC，它再在 04:43、06:47 UTC 各叫一次，都经 GitHub 接口按正式的输入触发。流程文件里还有 GitHub 自己的定时 04:17、05:11 UTC，11-10 实测从没准点触发过，留着不动（来了也因为认领跳过）。定时没有输入项，一律按正式走。
- **同一天只出一期**：第一段 `claim` 往仓库推标签 `issue/<日期>` 认领，推上去的那次才出刊，其余一分钟左右跳过；第 4 步以前出错自动放回标签、下一个时刻再试，第 4 步以后出错标签留着、发邮件。测试运行和接着跑不认领。周六正式运行只跑第 1–3 步。详见 `云端全流程_2026-11-08.md` 第一节。
- **手动**：GitHub 网页 Actions → frontier-daily → Run workflow。输入项的默认值都是测试那一边，各项含义见仓库首页 `README.md`"云端怎么运行"一节。
- **保底触发器的部署、核对、停用**：Actions → 保底触发器 → Run workflow（`trigger-deploy.yml`），见 `密钥与重置手册.md`"Cloudflare 保底触发器"一节。

测试和正式的区别：

| | 手动触发（测试默认） | 定时触发（正式） |
|---|---|---|
| 跑到第几步 | 9 | 17，接着审片、放行（周六只到 3） |
| 认领这一天（同一天只出一期） | 不认领 | 认领（标签 `issue/<日期>`） |
| 配音 | MiMo 备用声音，Gemini 不花钱 | Gemini 主声音，每期最多 $0.6、每月 $8 |
| 配图 | 程序封面 | Codex 先画，画不成的那张用程序封面 |
| 视频导演（旁白也归导演写，过了检查才重配视频旁白） | 开，但不新画图；重配旁白用 MiMo 备用声音 | 开，可以新画图；重配旁白用 Gemini，每期最多 $0.10 |
| 发布 | 不发 | 仓库变量 `SITE_DEPLOY_ENABLED` 为 `true` 才发，现在没设 |
| 邮件 | 只打印 | 真发 |
| 跨天状态（事件库、账本、这期文字） | 不提交 | 提交回 main |

日期不能选仓库 `测试版/` 里已经有的那几天，否则程序会把那几份文字当成"已经做过"。

## 产物在哪、留多久

- 发布了的那期：网站 `wenlongzhang.com/frontier`，底稿存在仓库的 `site-archive` 分支，不清理。
- 每期文字、事件库、账本：提交回 main，不清理。
- 没发布的那期：运行页面最下面的产物，带音频视频，留 7 天，这期间可以用"手动放行"发出去（手动放行那条流程还没实测）。
- 日志和中间文件：同样留 7 天。
- 本机看成品：在仓库根目录运行 `python3 cloud/取回成品.py`（默认今天，`--date` 选别的一天），把那天正式运行的两份产物（`media-`、`issue-`）拼回一份完整的期目录，放进成品库 `本机资料/成品/<日期>/`，`10_网页v3/index.html` 双击能看；已经有的日期不覆盖（加 `--force` 才重取，旧的移进废纸篓）。顺带清理：成品库里满 7 天、并且已经发布到网站（`site-archive` 分支里有）的期移进废纸篓，没发布的不动；`--dry-run` 只列不动。mini 上每天约 08:30 定时运行它，见 `云端全流程_2026-11-08.md` 第四节"取回成品"。
