# 网页稿：周六、周日和工作日不同的地方

> 谁读：写周末网页稿的模型。程序把这一份接在《写稿_网页.md》后面一起给你（`run_mimo.py write` 周六、周日这样拼）。这里只写和工作日不同的地方，没写到的一律照《写稿_网页.md》。2026-11-01 晚按 `文档/方案/周末版与声音规范.md` 第二、三节写；同晚按协调人建议改了版面（首屏卡、名词解释、周日不单列今日数字）。网页上怎么画，见 `site/v3/app.js` 的 secCardWeekend、secDeep、glossaryBox；版面上限在 `site/tools/v3_site.py` 的 WEEKEND。

## 一、版面（从上到下）

| | 周六（快讯＋深度） | 周日（本周深谈） |
|---|---|---|
| 首屏卡 | **今日深度**：深度题的大标题、一句话（`summary_zh`）、"听深度"，下面两三条快讯标题 | **本周深谈**：大标题、核心问题（`question_zh`）、一句话结论（`conclusion_zh`）、"听深谈" |
| 往下 | 今日数字（最多 4 格）→ 看与听 → 快讯（5–6 条）→ 深度（各层、名词解释）→ 预告看板（有才放）→ 参考来源 | 看与听 → 本周深谈（五层、时间线、各层的关键数字、名词解释）→ 本周快讯（3–4 条）→ 接下来看什么（有才放）→ 参考来源 |
| 没有的 | 头条、要闻、今日一词 | 头条、要闻、今日一词、今日数字 |
| 国内外对照 | 0–1 组，只在深度那一题天然有国内对应时 | 同左 |

- `sections` 里不写 `headline`、`brief`，**也不写 `term`**（今日一词改成深度那一条里的 `glossary`，见第二节）。深度／深谈那一题写成一个 `{"kind": "deep", "items": [一条]}`，条目的 `id` 就是专题卡编号（选题的 `deep.card_id`，默认 D1）。
- 栏目名页面按星期几自己写（周六"今日深度""深度"，周日"本周深谈""本周快讯""接下来看什么"），你不用写。
- `daily_card`：
  - 不写 `term`；
  - 周六 `headlines` 写 2–3 行**快讯**的短标题（每行不超过 18 字，从快讯里挑最值得点开的），不要再写深度那一题，它已经是卡片的大标题；
  - 周日 `headlines` 写空列表 `[]`（首屏是本周深谈卡，不列三件事）。

## 二、深度／深谈那一条怎么写

网页是给人扫读和查证的，不是播客的文字稿：周日也写成一篇文章，不写成两个人的对话；按"层"分段，每层先给结论。

- `title_zh`（≤ 22 字，首屏卡上的大标题）、`summary_zh`（≤ 60 字，写那个反差和核心问题；周六首屏卡上的"一句话"就是它）、`tab_zh`（≤ 12 字）；英文同理。
- **周日必写**（首屏卡上用）：
  - `question_zh`：核心问题，一个问句，≤ 40 字，照播客开场 Dylan 抛出的那个问题写；
  - `conclusion_zh`：一句话结论，一个判断句，≤ 40 字，照播客结尾"目前能确定的"和各层结论收成一句，不加新事实；
  - 英文 `question_en`、`conclusion_en` 按英文读者习惯重写。周六不写这两项。
- `body_zh` 按层写。每一层以一个**层标题段**开头，格式是一整段 `【层名】这一层的结论`（结论 ≤ 20 字，是一句判断，不是问题），后面跟 1–3 个短段落。层名一字不差：
  - 周六 3 层：`发生了什么`、`为什么重要`、`接下来看什么`；
  - 周日 5 层：`来龙去脉`、`怎么做到的`、`数字怎么读`、`各方怎么看`、`意味着什么`。
  例：`【数字怎么读】榜首只领先一分，口径还不一样`。页面把层标题段画成小标题，把结论当这一层的摘要，并在旁边放"听这一层"（跳到播客里同名的那一章）。
- `body_en` 层数和顺序与中文一样，层标题段写成 `【What happened】…`、`【Why it matters】…`、`【What to watch】…`（周日：`【The week】`、`【How it works】`、`【Reading the numbers】`、`【Who says what】`、`【What it means】`），按英文读者习惯重写，不逐句翻译。
- 每一层正文 80–220 字（周六全篇 400–700 字，周日 650–1,100 字）。数字、引语、出处规矩和工作日一样，每个事实都能挂上专题卡里的出处。
- 官方没公开的写"官方没有公开"；第三方说法写明是谁测的、怎么测的。
- `why_zh` 写转述的判断（谁说的），`read_zh` 写我们的理解（一两句）。
- `numbers`（这一题的关键数字，都从专题卡来，带 `source_id`）：
  - 周日：每个都写 `"layer": "层名"`（中文层名，一字不差），页面把它放在那一层正文下面；**每层最多 3 个**，合计 4–8 个；没写 layer 的放进"数字怎么读"。已经画进图表的数（比如柱状图里的几个分数）不再重复做数字卡；
  - 周六：3–6 个，不写 layer 的放在深度那一块最上面；写了 layer 的也放进那一层。
- `glossary`（**名词解释**，代替今日一词）：收 3–5 个这一期正文里出现、普通读者可能不懂的术语，按出现的层排好。每个
  `{"zh": "留出测试", "en": "held-out test", "explain_zh": "", "explain_en": "", "layer": "数字怎么读", "source_id": "s9"}`：
  - `explain_zh` 一两句、≤ 80 字：先说它是什么，**照播客稿里的说法写**（稿子里"也就是……""就是……"那一句）；稿子没解释的，用专题卡 `terms` 里的解释；再用一句接回这一期（"Carbon 测得 11%，比 Argon 高"）。不加卡片外的新事实，数字照卡片；
  - `layer` 写这个词出现的层，页面会注明"出自第几层"并能跳过去；`source_id` 只在解释里用到了这一期的事实或数字时写；
  - 往期当过今日一词的词（`02_选题/往期今日一词.json`），中文名沿用当时的写法（有"定名"的照定名，比如 open weights 写"开放权重"）；名词解释不要求回调，程序只提醒；
  - 周六播客没有"今日一词"这一章，周日播客结尾说"名词解释在网页上"，所以两天都要写。
- `related`：用到的其他事件卡（比如作为"国内对应产品"的那一条），写一句关系说明。

## 三、page 的差异

- `numbers`（今日数字）：
  - 周六 **最多 4 个**，从快讯和深度里取（深度至少 1 个），`story` 写事件号或专题卡编号；和快讯标题里已经写出来的数重复的不放；
  - 周日 **不写**（写空列表 `[]`）：关键数字写在深谈那一条的 `numbers` 里，带 layer。写了也会被程序去掉并提醒。
- `watch`（预告时间轴；周日页面上叫"接下来看什么"）：深度"接下来看什么"、深谈"意味着什么"里有出处的日子都放进来，`story` 写专题卡编号。
- `charts`：可以给图表加一个 `"layer": "层名"`（中文层名），页面就把它放在那一层下面；不写就放在整块的最后。`story_charts` 可以写 `{"D1": [图表名]}`，组装程序认。周日"来龙去脉"放一张时间线（这一周的 3–5 个节点），"数字怎么读"最好有一张同一口径的对比图；口径不同的数不画在同一张图里。
- `term_like`：周末不写（没有今日一词）。
- `images`：深度／深谈那一条要配图（键是专题卡编号），日卡照旧；快讯不配图。首屏卡没有日卡配图时用深度那一条的图。
