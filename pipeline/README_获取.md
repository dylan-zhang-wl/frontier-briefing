# 获取＋归并测试流水线（README）

2026-10-31 写，测试版。三步：**抓取 → 粗筛 → 归并成事件**，全程不调用大模型、不登录、不碰 X／Reddit／公众号，本机约 40 秒跑完。

## 一、怎么运行

```bash
cd <仓库根目录>
PY=~/.venvs/frontier-daily/bin/python
$PY pipeline/fetch.py     --day 2026-10-31 --since 2026-10-29T12:00:00Z   # 约 10 秒
$PY pipeline/prefilter.py --day 2026-10-31                                 # 约 3 秒
$PY pipeline/cluster.py   --day 2026-10-31                                 # 约 20 秒（含加载向量模型）
```

- `--day` 决定输出目录 `测试版/<day>/`；不给就用今天（UTC）。`--since` 不给时，默认运行日 00:00 UTC 往前 36 小时。
- 调试单个来源：`$PY pipeline/fetch.py --only openai,qbitai --out-dir <临时目录>`（给 `--out-dir`，免得覆盖正式输出）。
- 依赖都在 `~/.venvs/frontier-daily`（uv 建的）：feedparser、httpx、pyyaml、numpy、beautifulsoup4、lxml、sentence-transformers（含 torch）。
- 向量模型 `sentence-transformers/LaBSE` 已缓存在 `~/.cache/huggingface`（1.8 GB），`cluster.py` 自动设 `HF_HUB_OFFLINE=1` 离线加载；Mac 上有 MPS（苹果芯片的 GPU）就用 MPS，否则用 CPU。

## 三、每一步做什么

### 1. 抓取 `fetch.py`

- **七层来源**：国际一手 14（OpenAI、Anthropic 社区源两个、Google 四个、MSR、NVIDIA 两个、Apple ML、Mistral、HF 博客、Meta 新闻室）；中国一手 15（Hugging Face 按组织列新模型 12 个组织：deepseek-ai、Qwen、moonshotai、zai-org、MiniMaxAI、stepfun-ai、ByteDance-Seed、tencent、XiaomiMiMo、baidu、inclusionAI、meituan-longcat；GitHub 发版 2 个：qwen-code、kimi-code；另有 1 个"中国实验室 GitHub 新建仓库"，查 10 个组织）；国际媒体与商业 12；中文媒体 8；社区信号 4（HN top＋best、HF 每日论文、GitHub 近 7 天新仓库星数榜、Product Hunt）；二手整合 5；语言翻译教育 4。
- 组织名 10-31 都实测存在。没找到可用 RSS 的：界面（超时）、第一财经（404）、财新（404）、华尔街见闻（空）、机器之心（只有公众号），已跳过；虎嗅、钛媒体暂代商业视角。WSJ 旧地址停更，换成道琼斯新地址。
- **礼貌抓取**：同一网站同时最多 2 个请求（HN 接口 8 个、Hugging Face 3 个），全局最多 12 个；单个请求超时 20 秒；超时、网络错误、429（请求太多）、5xx（服务器错误）最多重试一次，等 3 秒；其余 4xx 不重试。自报身份 `frontier-daily/0.1`。
- **统一与清洗**：HTML 转纯文本、去掉"The post … appeared first on …"之类的套话，摘要截到 600 字；按标题里汉字和字母的比例判 zh／en；时间统一成 UTC。中文源若出现"比现在还晚"的时间，按"北京时间误标成 UTC"减 8 小时。
- **时间窗口**：只留 `--since` 之后的。例外：GitHub 新星榜是快照（按要求取近 7 天新建的仓库），不受窗口限制，热度里的时效衰减照常按建库时间算。
- **特殊处理**：Techmeme 标题末尾的"(作者/媒体)"拆出来，网址换成原文链接；Hugging Face 同一系列的量化版、不同尺寸合成一条，并读模型卡开头做摘要；GitHub 发版去掉 canary／nightly／rc 等测试版。
- **AINews 社交信号**：每期本身记一条（layer=aggregator）；"AI Twitter Recap"里每个带 x.com 帖子链接的列表项记一条 X 信号（作者、要点、帖子链接，layer=social），发帖时间从帖子编号解出（X 的编号里含毫秒时间戳）；"AI Reddit Recap"每篇帖子记一条（标题、版块、Activity 数）。只读 AINews 订阅源里已有的文字和链接，不访问 X、Reddit。
- **网址去重**：网址规范化（主机名小写、去 www.、去 utm_ 等追踪参数和锚点）后同一网址只留一条，层级高的优先（一手＞媒体＞二手＞社区＞社交）；被并掉的来源记在 `extra.dup_sources`，HN 分数等互动数据并进来。归并时这些来源仍算独立来源（比如 HN 帖子和 WSJ 原文是同一个链接，两边都算）。

### 2. 粗筛 `prefilter.py`（宁宽勿严）

规则按顺序：

1. 会议门票广告剔除。
2. 来源本身专讲 AI（YAML 里 `ai_focused: true`）或 AINews 社交信号 → 一律保留。
3. 标题像导购（价格＋"到手／国补／发售"等词）且标题里 AI 词少于 2 个 → 剔除。
4. 综合来源：**标题**里有 AI 强词或 AI 实体（公司、模型、芯片，中英文都认），或标题有 2 个弱词，或摘要里有 2 个以上不同的强词／实体 → 保留（AI 相关）。只看摘要零星提一句 AI 的数码稿、社会新闻不收。
5. 标题里有科技公司＋商业／安全／政策词，或标题有商业／安全词而摘要里有科技公司 → 保留为"科技商业"。
6. 其余剔除，理由写"未命中 AI／科技商业词表"。

另外：中文早报（如"9点1氪丨A；B；C""A；B；C｜极客早知道"）按分号拆成子条目分别粗筛、分别参与归并；英文汇总稿（TLDR 每期、WSJ Market Talk 等）标为 roundup，归并时只记"提及"。每条都给相关度（ai／lang_edu／tech_business）、主题标签（模型发布、价格套餐、融资上市、财报股市、算力芯片、政策监管、编程智能体、机器人驾驶、研究论文、安全风险、语言教育）和"主体属中国还是国际"（按命中的公司判断）。

### 3. 归并 `cluster.py`

- **句向量**：LaBSE 是谷歌训练的多语种句向量模型，把一句话变成 768 个数字，意思相近的句子数字也相近，中英文可以直接比；"余弦相似度"衡量两串数字有多接近，1 表示几乎一样。编码内容是"标题＋摘要前 300 字"。
- **专名**：从标题里抽公司、产品、人名（中英文写法归一，如 英伟达→nvidia、奥尔特曼→altman、币安→binance）、带数字的型号（Gemini 4→gemini4）、金额（$6.3B 和"63 亿美元"都记成 $6.3b）、百分比。
- **合并**：凝聚式聚类（先把最像的两组合并，再算新组和其余各组的相似度，直到最像的一对也不够像）。两组的"调整后相似度"＝质心余弦＋专名加分－专名减分，≥ 0.78 才合并。

| 两组标题里的专名 | 加减分 | 相当于余弦要达到 |
|---|---|---|
| 没有可比的专名（至少一边没有） | 0 | 0.78 |
| 都有专名但一个也不重合 | −0.05 | 0.83 |
| 只共有 1 个"枢纽"专名（openai、claude、google 这类天天出现的大公司，名单见代码 `COMMON`） | +0.08 | 0.70 |
| 只共有 2 个枢纽专名 | +0.14 | 0.64 |
| 共有 1 个少见专名（如 cursor、intel、qwen4） | +0.16 | 0.62 |
| 共有 2 个以上少见专名，或 1 少见＋1 枢纽 | +0.20 | 0.58 |

  金额、百分比单独重合只按枢纽专名算（OpenAI 的 $30B 目标和 Baseten 的 $30B 估值是两回事）；GitHub 新星榜条目不吃加分。

- **为什么是这些数**：先在 10-31 这批 549 条上看 LaBSE 的相似度分布（每条与最近邻的余弦中位数 0.59；任意两条的 99% 分位 0.52），再按相似度分段抽样逐对看：
  - 同一事件、同一语言的近似标题多在 0.85 以上；同一事件的中英文稿在 0.60–0.82（Apple 智能入华 IT之家对 The Verge 0.70，Cursor 插件被投毒 0.69–0.71，英特尔暴跌 虎嗅对 Techmeme 0.69，Altman 谈内存 0.75–0.82）；
  - 但同一天、同一领域的不同事件也常落在 0.60–0.80（"茅台三季报"对"摩尔线程三季报点评" 0.77，"摩尔线程三季报"对"长鑫签长期供货协议" 0.80，两个不相干的 GitHub 智能体仓库 0.67）。
  - 所以只看余弦分不开，要用"有没有共同专名"把两者拉开；0.78 这条线让没有专名证据的稿子只有很像才合并。调参后又把合并线下方 0.66–0.78 的"差一点没并上"的 45 对逐一看过，按真并／误并调了加分档位。阈值只凭这一天的样本定，需要用户标注 100–200 对再校准。
- **独立来源**：同一运营方只算一次（NVIDIA 博客＋新闻稿算一个，Google 四个博客算一个，同一媒体多篇算一个）；网址相同被并掉的来源也算；X 信号按发帖人算，Reddit 按帖子算。
- **热度公式**（`heat()`）：

  ```
  heat = R × ( Σ_独立来源 w(层级) × 0.5^(距今小时 / 36)  ＋  E )
  w：国际一手／中国一手 1.5；国际媒体／中文媒体／语言教育媒体 1.0；社区信号 0.8；二手整合 0.6；社交信号 0.4（最多计 4 个）
  距今小时：该来源在本事件里最近一次出现，到本批数据最新时刻的小时数；半衰期 36 小时（窗口约 45 小时，用 24 小时会把前天下午的大事压得太低）
  E（互动加分，各项取事件内最大值，合计封顶 1.2，约等于多一个媒体来源）：
    0.4·log2(1+HN 分数/100) ＋ 0.3·log2(1+HF 论文点赞/100) ＋ 0.3·log2(1+GitHub 星数/1000) ＋ 0.3·log2(1+Reddit Activity/1000)
  R（相关度折扣）：事件以 AI 或 AI×语言教育为主 1.0；只是科技商业 0.6（落实"AI 为主、科技商业为辅"）
  ```

- **代表标题**：中英文各取一条原文标题，媒体标题优先（最能说清"发生了什么"），其次官方标题，同层取最贴近事件质心的一条；没有某种语言的报道就留空，不翻译。
- **中外都有报道**（`cn_and_intl`）：正式报道（一手、媒体、二手、语言教育媒体）里中国来源和国际来源都有。另给 `cn_and_intl_any`，把社交、社区信号也算上。
- **相关事件**：未合并的两个事件质心余弦 ≥ 0.55，每个事件最多列 4 个。
- **中外对照**：一边主体是中国公司、一边是国际公司；标题里有共同的具体主题（模型发布、价格套餐、融资上市、算力芯片、政策监管、机器人驾驶、安全风险、财报股市）；两边都是像样的 AI 事件（≥2 个来源、或官方一手、或热度 ≥ 0.6 的正式报道），至少一边 ≥2 个来源；质心余弦 ≥ 0.35（主体不同的两件事本来就不太像，主要靠主题配对）。排序分＝0.5×余弦＋0.3×两边热度较小者，每个主题最多 4 对。

## 五、已知问题

1. **归并仍有漏并和误并**。漏并：Anthropic 信用评级（FT 与 TechCrunch 已并，虎嗅"垃圾级"一文没并上）、"科技股因 AI 支出暴跌"分成好几个事件、Anthropic 禁止"AI 复刻游戏"中英文三条没并。误并：Altman 谈数学、Altman 会见三星被并进"Altman 谈内存"；"中国团队世界模型力压 Genie 4"被并进 Genie 4（标题里都有 Genie 4）。根子在 LaBSE 擅长找译文，不擅长判断"是不是同一件事"；下一步可以接 AIHOT 的"同一事件"模型复核（只复核 0.66–0.85 这一段）。
2. **中国一手很薄**：45 小时里 Hugging Face 和 GitHub 只来了 5 条（蚂蚁 ZwZ2、Qwen Code、Kimi Code 发版）。中国公司的新闻主要靠中文媒体和 AINews 转述；官方博客、公众号没接。
3. **财经媒体 RSS 没找到**（界面、第一财经、财新），中文商业视角只有虎嗅、钛媒体、36氪。
4. **时间精度不一**：Anthropic 社区源只到日期，HF 每日论文是上榜日 00:00，Reddit 信号用 AINews 那期的发布时间；窗口边界附近可能多收或漏收。
5. **社交信号是 AINews 的转述**，不是原帖；142 条占了不少比重（已限制每个事件最多计 4 个、权重 0.4）。AINews 改版面结构时解析会返回空（不报错），要看每源统计里"拆出 X 信号 N 条"。
6. **粗筛词表是手写的**：仍有少量误收（虎嗅长评论、汽车智驾配置更新）和可能的漏收（标题不含任何列表词的 AI 稿）。加密货币被盗（币安 63 亿美元）按"科技商业"保留，热度打 0.6 折后排第 6。
7. **主体地区和主题标签靠词表**，评论类长文常被判成泛主题，中外对照里还有几对凑数的（如"王兴兴杀入 VC"对美股科技股下跌）。
8. **单条高分 HN 帖**（如 AI 与运维、AI 泡沫救助决议）能排进前 20，这是"互动加分"的设计结果；只想看新闻事件时可调低 E 的系数。
9. **来源侧**：VentureBeat 偶尔返回 429（请求过多），重跑即可；Microsoft Research 会拦某些自报身份写法（UA 已改成可用的写法）；The Information、WSJ、FT、彭博只有标题和摘要。
10. 前 60 名的后半段多是单一来源事件（热度 0.9–1.0），是正常现象：一天里大多数事都只有一家报道。
