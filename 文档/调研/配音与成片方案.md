## 0. 结论速览

1. **主力配音**：继续用 Gemini 3.8 Flash TTS 做单人主播（沿用已有的设计音色），按段落分块生成，每段再用 Whisper 转写对稿。每月约 $4.9；2027-01-01 起单价翻倍，约 $9.8。当时那笔赠金覆盖到 2027-01-25 绰绰有余，但赠金也在被其他用途消耗。
2. **状态更新**：Vertex（已更名 Gemini Enterprise Agent Platform）文档现在把 3.8 Flash TTS 列为 **GA（2026-10-28）**，区域有 global、us、eu 三个。声音设计和声音复刻所用的 Voices API 仍是 Preview，并且只在 global 区域。
3. **免费备用**：MiMo-V2.5-TTS。按量付费和 Token Plan 两条路目前都写"限时免费"，官方没有公布截止日期。
4. **付费中文备用**：豆包语音合成 2.0（约 ¥34/月）或 MiniMax speech-2.8-hd（国内站约 ¥77/月）。
5. **现成双人播客**：豆包"语音播客大模型"API，固定 2 人，可以直接传入自己写的对话脚本。约 ¥68/月。需要火山引擎账号并完成实名；人在英国能否顺利开通和调用，没有查到说明。
6. **双人对话的限制**：Gemini 单个请求最多 2 个说话人，而且只能用预置音色。设计音色要做双人，只能逐句分别合成再拼接。
7. **本地开源**：在 M2 16GB 上能跑的主要是 1–2B 规模的模型。效果最好的对话模型（MOSS-TTSD v1.0 8B、Fish Audio Drama 3 35B MoE）跑不动，另有几款许可不允许商用。只适合做兜底或试验。
8. **分发**：自建 RSS 可以进 Apple、Spotify 和小宇宙。但 Apple 的文字稿功能不支持中文，Spotify 不读 RSS 里的文字稿，三家的章节写法各不相同。小宇宙对实名和手机号的要求没查到官方说明。
9. **视频**：第一步用 ffmpeg 做"图卡＋字幕＋音频"；需要动画和动态图表时再上 Remotion 或 HyperFrames。封面和配图用 Nano Banana 2.1，1K 图每张 $0.0336。

### 1.2 中文质量的公开证据（结论：没有可靠的中文专项评测）

- **Google 自评**：Hume AI 声音设计基准第一（71.4）；称在"日语、巴西葡语、印地语等多种语言"的盲测偏好中领先，没有点名中文。【已核实（官方博客），属厂商自评】
- **Artificial Analysis 总榜**：把 Gemini 3.8 Flash TTS 列为"性价比最好"的几款之一；质量最高的是 Eleven v4 Turbo（Elo 1336）。【部分核实】
- **Artificial Analysis 普通话"受控声音"榜**（AlphaSignal 2026-09-22 的二手报道）：前三是 Inworld Realtime TTS-2（1,185）、Cartesia Sonic 3.6（1,146）、阶跃 StepAudio 2.5 TTS（1,130）。Gemini、ElevenLabs、MiniMax、豆包的名次没有披露。【未核实（二手）】
- **风险信号**：Google 开发者论坛从 2026-09-30 起有帖子反映，3.8 TTS 在 2–7 分钟以上的长生成里会出现几种问题：音色或性别突变、响度跳变、多念原文没有的词、10–20 毫秒的爆音。分块请求、固定预置音色都没能消除。官方 10-15 回复"正在调查"，到 10-19 仍没有修复。帖子测试的是英语、保加利亚语和德语，没有涉及中文。【已核实（论坛原帖）】
- **社区零星反馈**："中文基础读音错误多"，大多针对早期的 2.5。【未核实】
- **小结**：判断中文效果要靠用户自己做盲听 A/B（方法见第 9 节）。用户在数字人项目里用这个模型的实际经验，比上面任何一条公开证据都更直接。

### 1.3 对本项目的含义

- 一期 12 分钟至少要 2 次请求（单次上限约 10.9 分钟）。实际建议按段落切成 60–120 秒一块，方便逐段对稿和重录。
- 用现有的设计音色做**单人主播**最顺手。做**双人**时有两条路：
  - 想让两人在同一个请求里自然接话、互相附和，只能换成 2 个预置音色；
  - 坚持用设计音色，就只能逐句合成再拼接，接话的自然度会差一些。
- 2027-01-01 涨价发生在赠金到期（2027-01-25）之前，最后三四周会按新价扣赠金。
- NotebookLM Enterprise 的"Podcast API"据 2026-05 的二手报道已经弃用，不建议依赖。【未核实】

**实操提醒**：
- 用户已经遇到过长文本"跑飞"（多念、复读）。应坚持分块生成，并用 Whisper 转写对稿。
- 推断：voicedesign 模型不接受 `voice` 字段，每次请求都按描述重新"设计"一次音色，分块之间可能对不上。更稳的做法是先挑一条满意的设计样音，之后所有分块都用 voiceclone 加同一条参考音频生成。【推断，未实测】

### 5.2 RSS 写法示意（Podcasting 2.0）

```xml
<rss version="2.0"
     xmlns:itunes="http://www.itunes.com/dtds/podcast-1.0.dtd"
     xmlns:podcast="https://podcastindex.org/namespace/1.0">
  <channel>
    <!-- 私人订阅时才加下面两行；公开上架时删掉 -->
    <itunes:block>Yes</itunes:block>
    <podcast:block>yes</podcast:block>
    <podcast:locked>yes</podcast:locked>
    <item>
      <enclosure url="https://…/2026-10-30.mp3" type="audio/mpeg" length="…"/>
      <!-- 章节：JSON 文件（Apple 26.2+ 和多数 2.0 客户端认） -->
      <podcast:chapters url="https://…/2026-10-30.chapters.json" type="application/json+chapters"/>
      <!-- 文字稿：带时间轴的 VTT；rel="captions" 表示字幕 -->
      <podcast:transcript url="https://…/2026-10-30.vtt" type="text/vtt" language="zh-cn" rel="captions"/>
    </item>
  </channel>
</rss>
```

- 各标签的属性名以 podcastindex 规范为准【已核实】：`podcast:transcript` 有 url、type、language、rel；`podcast:chapters` 的 type 用 `application/json+chapters`；`podcast:block` 的值只能是 yes 或 no，可以用 id 指定只屏蔽某个平台。
- 兼容三家的写法：章节 JSON 加 ID3 章节，**同时**在简介里写时间戳。这样 Spotify 和小宇宙也能显示章节。
- 托管：任何支持 HTTPS 和断点续传（Range 请求）的静态托管都可以。12 分钟的单声道 MP3 按 64–96 kbps 编码，每期约 6–9 MB。这一条按常识写的，没有逐条核对。

### 5.3 只给自己听的私人订阅

1. RSS 和音频放在自己的站点或对象存储上，用一个很长、别人猜不到的路径。RSS 里加 `itunes:block` 和 `podcast:block`，不向任何目录提交。
2. 订阅方法：Mac 的播客 App 用"文件 > 通过 URL 关注节目"；iPhone 在"资料库"的"…"菜单里选同名入口；Overcast 等第三方客户端也能用 URL 添加。【Mac 路径已核实（Apple 支持页），iPhone 路径部分核实】
3. 需要密码时可以加 HTTP Basic Auth。Apple 的旧文档说支持 Basic 和 Digest 认证；Apple 社区 2025-12 的回复说，私有 feed 的凭据不会在设备之间同步，每台设备要各加一次。【部分核实】
4. 注意：
   - Apple 不会为私有 feed 生成文字稿。
   - 旧资料说，把 feed 地址粘贴到小宇宙的搜索框会被提交收录，等审核后可能被公开搜到。私人订阅不要在小宇宙里粘贴地址。【未核实】

### 5.4 合规提醒

- **新闻版权**：用 LLM 归纳、改写，并写明来源。不要整段朗读原文，公开发布时尤其要注意。只给自己听的风险低很多。
- **AI 披露**：Apple 指南 1.11（元数据里必须披露）；YouTube 要求对逼真的合成内容做披露（见 6.4）；上架国内平台要遵守《标识办法》。建议每期片头加一句"本节目由 AI 合成"，节目简介里也写明。

### 6.2 建议流水线

1. **字幕**：口播稿本来就有，不需要重新识别，只要做"强制对齐"，即把已知文字和音频的时间点对上。可以用 WhisperX 一类工具，Mac 上有 MLX 版的 whispermlx；中文对齐模型的效果要实测。如果豆包播客生成音频，它每一轮结束时会给出起止时间，可以直接拿来做章节和分段。
2. **图卡**：用 HTML 模板渲染成 PNG，分标题卡、要点卡、来源卡。**数据图一律用代码画**（ECharts、Vega-Lite、Matplotlib），不要让图像模型画，它画的数字会出错。
3. **封面**：用 Nano Banana 2.1 生成无字的背景图，中文标题再用代码叠上去，避免图像模型把汉字写错。
4. **合成**：第一阶段用 ffmpeg 合成 16:9 的 1080p 视频；第二阶段需要动画时，再换 Remotion 或 HyperFrames。

## 8. 推荐组合，以及单人和双人怎么选

### 8.1 配音组合

| 角色 | 方案 | 理由 | 主要风险 |
|---|---|---|---|
| 主力 | Gemini 3.8 Flash TTS，单人，用设计音色 voice ID，`style` 留空或写短 | 已有现成流程和赠金；整体质量第一梯队；成本低 | 长生成里音色漂移（论坛未修复）；中文公开评测少；2027 年涨价；声音设计仍是 Preview |
| 免费备用和 A/B 对照 | MiMo-V2.5-TTS，用 voiceclone 加固定参考音频 | 现在零成本；国产中文模型 | 免费期随时可能结束；长文本跑飞 |
| 付费中文备用 | 豆包语音合成 2.0 或 MiniMax 2.8-hd | 中文原生；按字符计费，费用好预估 | 要开国内或国际账号；MiniMax 汉字按 2 字符计 |
| 双人现成方案（试验） | 豆包语音播客（action=3，用自己的脚本） | 原生双人中文播客，接话自然；可选 AIGC 水印 | 约 ¥68/月；国内实名和从海外调用都未核实 |
| 本地兜底 | Qwen3-TTS（mlx-audio） | Apache-2.0，可离线，M2 能跑 | 质量和速度都要实测；没有对话能力 |

**质量控制**（不论选哪家都要做）：
- 每块 60–120 秒；
- Whisper 转写后和原稿比对字错率，超过阈值就重录；
- 推断性建议：再用说话人向量（声纹特征）比较每块和参考样音的相似度，自动发现音色漂移。

### 8.2 单人主播还是双人对话

- **每日 12 分钟新闻简报，建议先做单人**，理由有五：
  1. 信息密度高，12 分钟能讲 6–8 条；
  2. 每句话都能对应到来源，好核对；
  3. 能直接用已有的设计音色和品牌声线；
  4. 重录和剪辑的成本低；
  5. 字幕和视频更容易做。
- **双人的好处**：更好听，复杂议题可以用一问一答讲清楚。
- **双人的代价**：
  1. LLM 写的对谈容易加入"哇，这太有意思了"之类的废话，也容易冒出没有来源的引申，核对成本明显上升；
  2. 同样的信息量，时长大约要多两成（经验估计，未核实）；
  3. Gemini 想让两人在同一请求里自然接话，只能用 2 个预置音色；用设计音色只能逐句拼接，接话会显得生硬；
  4. 两人抢话时，Whisper 对稿更难做。
- **折中方案**：主体用单人播报，每期最后加 2–3 分钟"双人点评"（或每周一期双人深度）。这一段分别用 Gemini 多说话人（2 个预置音色）和豆包播客各做一版，盲听比较。
- **中英双语**：建议中文主播报加英文原句引用，或者另出一期英文版。同一音色在中英之间切换的效果要实测。

## 9. 待实测清单（建议下一步）

1. **盲听 A/B**：同一段 600 字中文新闻稿，要包含多音字、英文专有名词、数字和百分比、公司名。分别用以下模型生成：
   - Gemini 3.8 Flash（设计音色）
   - Gemini 3.8 Flash-Lite
   - MiMo voiceclone
   - MiniMax 2.8-hd
   - 豆包 TTS 2.0

   打乱顺序后由用户打分。客观指标用 Whisper large-v3-turbo（MLX 版）转写后的字错率。
2. **Gemini 长生成漂移测试**：12 分钟稿件切成 8 块，测每块的说话人相似度和响度，看论坛反映的问题在中文上是否出现。
3. **豆包**：在英国注册、实名、开通试用，跑一次 action=3，记录延迟和效果。
4. **小宇宙**：在 App 创作中心确认三件事：入驻和认领流程、是否需要实名或国内手机号、对 AI 合成节目的要求。
5. **Apple**：用一档测试节目，验证章节 JSON 在中文节目里能否显示。
