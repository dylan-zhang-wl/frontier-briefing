## 0. 怎么读这份报告

**数字口径**
- ★ = `stargazers_count`；最近推送 = `pushed_at`（任何分支最后一次 push，不等于正式发版）。
- 许可证 = GitHub 识别结果。"无"表示仓库里没有可识别的 LICENSE 文件，默认不授予复用权（即使 README 自称 MIT）。

**核实标记**
- ✅ = gh 元数据 + 亲读 README，并读了部分源码、提示词或配置文件
- ☑️ = gh 元数据 + 读了 README（或仓库描述），没读代码
- 🌐 = 只见于网页或第三方文章，仓库里核实不了

**几个术语（第一次出现时的通俗解释）**
- RSS / OPML：网站的"订阅源"/ 一批订阅源打包成的清单文件。
- 向量召回（embedding）：把文字变成一串数字，按"数字距离"找出意思相近的候选，再交给大模型细判。
- cron：定时任务的时间表写法；GitHub Actions 的 cron 一律按 UTC（格林尼治时间）。
- Cloudflare Workers / Workflows / R2 / KV / Pages：Cloudflare 的无服务器函数 / 可分步重试的工作流 / 对象存储（放音频、图片）/ 键值存储（放小数据）/ 静态网站托管。
- TTS：文字转语音。ASR：语音转文字。
- MCP：让 AI 助手（Claude Code 等）直接调用外部数据和工具的协议。
- AGPL / GPL：要求"改了就要公开源码"的开源许可；AGPL 连"作为网站对外提供服务"也算分发。借鉴思路没有问题，直接复制代码要按许可公开。

**检索方法**
- `gh search repos`：约 60 组中英文关键词和 GitHub 主题（如 AI 日报、AI 早报、newsletter generator LLM、hacker news podcast、topic:ai-news、topic:news-aggregator、topic:podcast-generator 等），按 stars 排序后筛"★≥100 且 2025-06 以后仍有推送"，再逐个 `gh api` 核实、读 README。
- WebSearch / WebFetch：查官方博客、第三方转述文章。
- X：WebSearch 的 `site:x.com` 过滤基本无效。改用 trendshift.io 各仓库页面上的"社交提及"找到帖子链接，再用 X 的公开嵌入接口（oEmbed，`publish.twitter.com/oembed`，网站嵌推文用的公开接口，不需要登录）逐条核对原文和日期。

## 4. 关键做法拆解（可直接借鉴的部分）

### 4.1 筛选与打分
- **两次独立打分 + 信源分级门槛**（AIHOT）：同一评分标准跑两遍，两遍都过、且过了该信源级别的门槛才入选；用一两百条自己标注的样本校准门槛。
- **按内容类型分别定标准**（Horizon）：新闻看"为什么重要"，技术长文看"能用上什么"；0–10 分档有文字定义（9–10 突破性 / 7–8 高价值 / 5–6 有趣 / 3–4 低优先 / 0–2 噪音）。
- **六维评分**（BestBlogs）：选题、内容、深度、实用、创新、表达。
- **先便宜后昂贵**：关键词粗筛（SuYxh、TrendRadar）→ LLM 精筛；X 纯链接帖不调写作模型（AIHOT）。
- **配额**：类别配额、总数上限（Horizon）；"头部厂商优先、同题只留最好一篇、写入选理由"（BestBlogs 早报）。

### 4.2 去重与"同一事件"归并
- AIHOT：近两周向量召回（没配向量服务就比文字重合度）→ LLM 判 4 种关系（同一次发生 / 同一事件后续 / 无关 / 汇总稿），并判断"相对已有内容有没有新信息"；拿不准的交第二个模型复核（复核说法来自第三方解读文章 🌐）。
- infinitum：先用"事件签名"快速匹配，再交 AI 判定。
- AINews：LLM 直接聚类，但用结构化输出（Zod）限定簇数与每簇条数，要求 ID 原样复制，重试时把"哪些已匹配、哪些没匹配"告诉模型。
- d33ply（2026 年 dev.to 文章 🌐）：Jaccard 相似度（词集合重合比例）阈值 0.7 去重。
- 热度：按事件、按**独立来源**计（AIHOT：48 小时内一个来源只算一次，24 小时减半）；"多源 N"标签（ai-news-radar）。

### 4.3 播客生成
- 共同结构：**先写稿、后配音**。稿件按行标注说话人 → 逐句（或逐段）TTS → 合并音频 → 上传对象存储 → 生成播客 RSS。
- 单人版：AI-Insight-Daily 的播客稿提示词（固定开场/结束语、5 分钟以内、末尾关键词）。
- 双人版：hacker-podcast 的角色设定（产品经理 + 工程师）与写作规则；Podcast-Generator 的"先大纲后对话"两段式。
- 声音选择：商用 API（MiniMax、火山、Gemini、ElevenLabs、Fish Audio、小米 MiMo）或自建开源模型（MOSS-TTSD、SoulX-Podcast，需要 GPU）。
- 已知坑：Gemini 分批 TTS 段间音色漂移（any-podcast 作者）；切段太碎导致停顿怪、整期过长（d33ply：30+ 片段 → 改为每节一段）；TTS 偶尔吞字跳词，需要 ASR 转写回来与原稿比对（d33ply）；Edge TTS 是非官方接口；VibeVoice 长篇 TTS 已下线试用。若沿用 Gemini TTS，建议先做一期整稿一次生成与分段生成的对比试听。

### 4.4 部署与调度
- **GitHub Actions + Pages / Cloudflare Pages**：DailyBrief、agents-radar、ai-news-radar、AI-Search、Horizon 模板、follow-builders 中央 feed、TrendRadar。
- **Cloudflare Workers + Workflows + R2 + KV**：hacker-podcast、AI-Insight-Daily、any-podcast；Workflows 的"每步可重试、步间 sleep"很适合 TTS 这类慢且易失败的调用。
- **Docker + 数据库**：AIHOT（Postgres + pg-boss）、infinitum、clawfeed（SQLite），适合"可交互工作台"但要自备服务器。
- 调度细节：Actions 的 cron 只认 UTC（DailyBrief 用"每小时探测 + gate"）；公开仓库 60 天没有提交活动，定时工作流会被 GitHub 自动停用（[GitHub 官方文档](https://docs.github.com/en/actions/how-tos/manage-workflow-runs/disable-and-enable-workflows)）；把每次运行数据写回仓库被 TrendRadar 放弃，改存 R2/S3。

### 4.5 防编造与可追溯
- 提示词层："所有内容必须严格来源于原文"（AI-Insight-Daily）；"不写模糊来源；有具体来源就注明，没有就删除"（hacker-podcast）；"防止模型把原文没提到的公司写进标题"（AIHOT）；"脚本中的名字、数字必须出自检索结果"（Verticals）。
- 结构层：ID 原样复制 + 校验（AINews）；JSON 校验失败修复一次、仍失败就记空分（Horizon）。
- 呈现层：观察 / 已核事实 / 判断分层，判断附反向信号与失效条件（agent-pulse）；每条保留原文链接（几乎所有项目）。

### 4.6 成本数据点（均为作者自报，未独立核实）
- DailyBrief：DeepSeek 每天约 $0.01–0.02（月 < $1），Sonnet 月 < $2。
- AIHOT：示范源首轮 152 条约 930 次模型调用；之后视每日新条目数。
- Verticals：每条短视频约 $0.11。
- d33ply（🌐）：每期约 25 分钟双人播客约 $0.91（Opus 写稿约 $0.65，TTS 约 $0.15），每天 $5–10。

## 6. 共性规律与常见坑

1. **主流程已经趋同**：采集 → 预筛 → 打分 → 同一事件归并 → 写作 → 编排发布。差别主要在"谁来定标准"：AIHOT 把行业经验写进提示词并用样本校准，Horizon 按内容类型分 profile，BestBlogs 有编辑精审。去重从"标题关键词"转向"相似度召回 + LLM 判关系"，热度按独立来源而非文章数计算，可以抵抗一家媒体刷十篇。
2. **最脆弱的是信源层，不是模型层**：X 要付费 API、Apify 或 Nitter（AINews 还要手动过浏览器挑战），Folo 要 cookie，Reddit 要 session，公众号要转 RSS；Gmail 收信曾被封号。成熟项目都有信源分级、健康度监控和失败降级（ai-news-radar 无 key 跑规则分，TrendRadar AI 失败回退关键词，hacker-news-digest 远端失败用本地 Qwen）。
3. **播客是"稿件工程 + 音频工程"两件事**：稿件靠角色设定和严格行格式（"女：/男："）保证可解析；音频坑集中在长文本分段（音色漂移、停顿、吞字），需要 ASR 回听质检。免费的 Edge TTS 是非官方接口，长期公开节目不宜依赖。
4. **调度与托管的隐形限制**：GitHub Actions cron 只认 UTC，公开仓库 60 天无活动会停定时任务，频繁把数据写回仓库会被嫌弃（TrendRadar 已改存 R2/S3）；免费账号私有仓库开不了 Pages；Cloudflare 免费版单次运行子请求有上限（any-podcast 作者称 50），长流程要拆步接力。
5. **许可、版权与平台规则**：hacker-podcast、RSSHub、Folo、worldmonitor、UglyFeed 是 AGPL，TrendRadar、AI-Insight-Daily 是 GPL，BestBlogs、follow-builders、Twocast 没有 LICENSE 文件——借思路可以，直接搬代码前要看许可。公开站点做"外文全文翻译"有版权风险，摘要 + 链接原文更稳；Kagi 数据是 CC BY-NC；小红书 2026-03-10 发布治理公告打击 AI 托管运营账号（AutoContents README 提醒），自动发社交平台要谨慎。
