## 一、网页信息架构（改为"一屏一块、块内切换"）

从上到下：

1. **顶栏**：每日AI科技前沿简报｜日期选择｜中/EN｜深浅色。
2. **日卡**：日期、今日三件事、今日一词（配图），加"听 12 分钟""看 70 秒"两个按钮。
3. **今日数字**（新增，替代部分图文总结）：3–5 个当天最关键的数字做成会动的数字块，比如"−28.58% 英特尔单日""200 亿美元 OpenAI 新目标"。数字从 0 滚到实际值，点击跳到对应新闻。
4. **看与听**：电脑上视频和播客并排；手机上用"看／听"两个标签切换。
5. **头条舞台**：2–3 条头条共用一块地方。左边是标签，右边是主舞台：配图、三句话、一个交互图表、"为什么重要"、上标引用。每条有"▶ 听这一段"（播客跳到对应章节）和"看这一段"（视频跳到对应场景）。
6. **要闻卡片**：横向滑动，每张有生成的配图；点开在原地展开解读，同一时间只展开一张。
7. **快讯**：紧凑列表，一行一条。
8. **预告看板**：一条一行，带状态标签（传闻、预告、已排期、已兑现、落空）和"预计何时见分晓"；6–10 条，多了分页。往期的预告兑现了，会在当天自动标"已兑现"，这就是网页上的"互文"。
9. **国内外对照**：左国外、右国内，中间是关系说明和一条动画连线；多组用标签切换。
10. **今日一词**：插画加翻面卡片。
11. **参考来源**：折叠，默认前 5 条（按被引用次数），可展开全部。
12. **页脚**：一行 AI 生成说明、往期入口、反馈按钮。

**预期效果**：电脑上 5–6 屏看完，手机上约 10 屏；现在两者都要 20 屏以上。

## 二、可视化与动效："纸面＋控制台"

### 1. 视觉语言

- **两种气质交替**：读的部分（头条、要闻、来源）保持暖白纸面，安静易读；数据部分（今日数字、图表、关系图、视频）用深色"控制台"面板：细网格、等宽数字、发光细线、少量粒子。两种气质交替出现，形成节奏，也带来你说的科技感。
- **主题色随当天的主线微调**：比如"资本降温"偏冷青，"新模型发布"偏亮蓝。每天看起来不完全一样。

### 2. 图表工具

用 ECharts，开源（Apache-2.0）、中文友好、动画和交互都是现成的。打包进网站，不依赖外部网络，国内也能打开。

按数据的形状自动挑图，同一天尽量不重复：

| 数据长什么样 | 用什么图 | 例子（10-31） |
|---|---|---|
| 一个关键数字 | 会滚动的数字块，带涨跌箭头 | 英特尔 −28.58% |
| 之前和之后 | 哑铃图，或者拖动滑块对比 | OpenAI 目标 300 亿 → 200 亿，估值 1.4 万亿 → 1.25 万亿 |
| 几家公司比一个指标 | 动态排序条形图 | 各模型得分（只用核对过的数字） |
| 占比 | 环形图、方块图 | 回购占经营现金流 9.3% |
| 随时间变化 | 带注释的折线 | 股价、营收 |
| 钱或资源怎么流动 | 桑基图（带宽度的流向图） | 内存产能流向数据中心还是个人电脑 |
| 谁和谁有关 | 关系网络图 | 苹果、阿里、千问、Siri 之间的关系 |
| 一件事的来龙去脉 | 横向时间线 | 国行 Apple 智能：2024 年 6 月发布 → 7 月备案 → 10 月 31 日官宣 → 11 月 4 日测试 → 12 月推送 |
| 国内和国外 | 地图弧线，或左右分屏 | 国内外对照 |
| 每条新闻有几家在报 | "报道光谱"小条：中文几家、英文几家 | 每条都有，数据来自归并结果 |

**图表由程序把关**：先让模型根据事件卡提出"用什么图、放哪些数"，程序再检查每个数字都在事件卡里、有出处，才画出来。模型不能为了好看编数字。

### 3. 动效与互动

- 滚动到哪里，哪里的元素才出现；数字滚动，图表生长。
- 鼠标停在上标引用上，显示来源；点"听这一段"，播客跳到对应时间。
- 头条、要闻、对照都在原地切换，不跳页。
- 系统设置了"减少动态效果"时自动关掉动画。

### 4. 视频改版

现在的问题：每一幕都是"大字加一个数字"，没有运动。改为：

- **动画引擎**：用 GSAP（专业网页动画库，现在免费商用），配合 ECharts 和画布粒子。
- **按词对齐**：配音的对稿那一步已经在跑 Whisper，顺手取出每个词的时间，让画面元素在说到那个词的瞬间出现，像专业的解说视频。
- **场景模板库**：做 12–15 种，包括：动态标题、数字滚动、条形图生长、哑铃对比、时间线推进、引语逐字高亮、地图弧线、关系图生长、配图缓推、左右分屏对照、要点瀑布、带"故障"效果的预告（表示不确定）、结尾回顾宫格。
- **多样性规则**：同一类场景不能连着出现两次，每期至少用 4 种。配图用 Codex 生成，配视差和缓推效果。
- **以后要发 YouTube 或视频号**：把同一套动画逐帧导出成 MP4。你的 story-film-studio 已经有逐帧渲染引擎，可以复用。

## 三、播客改版

### 1. 声音与费用

- **实际费用**：Gemini 配一期约 $0.17，每月约 $5，2027 年起约 $10。2027-01-25 前由当时那笔赠金支付；之后你的会员每月送 $10 Google Cloud 额度，正好够用（要先在 my-benefits 页确认已经激活）。所以 Gemini 可以当主力。
- **情感为什么不够**：第一版只用了一句固定的风格说明，没有分段调整语气。改进：
  - 每一段单独给风格：开场温暖有精神，热点沉稳，快讯轻快，今日一词带点笑意；
  - 适当加停顿标记；
  - 稿子写成更口语的中文，少报媒体全名。第一次说"据彭博社"，之后用"报道还说"。
- **MiMo 也值得再试一轮**：它的"导演模式"（分层写角色、场景、语气）和中文行内标记，第一版都没用上。先用它的声音设计做一段满意的样音，再用声音复刻保持音色稳定。第二轮同一段稿子：Gemini 分段风格版对比 MiMo 导演模式版，你来听。
- **克隆声音**：可以克隆你自己的声音，做成"本人主播"，Gemini 和 MiMo 都支持。这有个人品牌价值，但涉及肖像与声音的使用边界，等你想好再说。

### 2. 不说"由 AI 生成"，怎么合规

- **现阶段只给自己和朋友听**：正文里不说；节目说明、音频文件信息、网页页脚写明即可。
- **将来公开上 Apple 播客或小宇宙**：两边都要求标注。办法有两个：
  - 片头放一段固定的短音乐作为"声音标识"。国内《标识办法》明确允许用"音频节奏提示"代替口头说明；
  - 结尾加一句很自然的话，比如"本期节目使用合成语音制作"，约 3 秒，不影响听感。
- **另一个边界**：主播不说自己是 AI，但也不冒充真人，不给它编人设和经历。

### 3. 背景音效

参照早咖啡，做一套固定的"声音包装"：

| 部件 | 时长 | 用在哪 |
|---|---|---|
| 片头曲 | 6–8 秒 | 开头，接着淡入问候 |
| 底乐 | 可循环 | 垫在开场和今日一词下面，主播说话时自动压低 |
| 转场音 | 1–2 秒 | 热点、要闻、快讯之间 |
| 片尾曲 | 8–10 秒 | 结尾 |

做法有三个，建议用 A 加 C：

- **A. Gemini 的音乐模型 Lyria**：30 秒一段约 $0.04，一次性做几段，花费不到 $1，从赠金里出。生成的音乐带隐形水印；商用条款要再看。
- **B. 免版税曲库**：许可清楚，但容易和别人撞。
- **C. 用程序合成简单的转场音和声音标识**：完全原创，没有版权问题。

混音用 ffmpeg 做"说话时自动压低音乐"（侧链压缩），最后统一响度。

### 4. 周末两种形式（第一版还没试）

- **周六深度**：单人主播 15–20 分钟，一个话题讲透，引语部分可以换第二个声音来念。
- **周日问答**：两个声音一问一答。Gemini 一次请求只能用 2 个预置声音，这样接话最自然；也可以用两个设计声音逐句合成后拼接。两种都试，你来听。

## 五、用量与模型分工

### 1. 为什么这次 MiMo 用了约 1.3 亿 credits

收集得多不是原因：抓取、粗筛、归并都在本机，不调模型。真正的大头是：

| 环节 | 估算 | 问题在哪 |
|---|---|---|
| 事件卡（12 次） | 约 0.7 亿 | 用了贵的 pro 档；每次塞进 3 篇原文；还有大量"思考"字数 |
| 写稿（3 次） | 约 0.6 亿 | 三份稿各发一遍全部 12 张卡，每次约 4.8 万 token，而且中英两份重复 |
| 选题（1 次） | 约 0.03 亿 | 本来就小 |

### 2. 怎么降

1. **事件卡改用 flash 档**：单价是 pro 的三分之一。抽取事实这类活，关掉"深度思考"（MiMo 官方有开关，要实测参数）。
2. **写稿只给必要字段**：每张卡只留核对通过的事实、数字和一句引语，不带英文副本。输入从 4.8 万降到约 1.5 万。
3. **共享开头吃缓存**：三份稿的输入放在同一个开头，第二、三次命中缓存，缓存部分的单价不到原价的百分之一。

**预计**：每天约 0.3 亿，每月约 9 亿，约占你的月额度两成。

### 3. MiMo 与 Claude 怎么组合

| 环节 | 谁来做 | 理由 |
|---|---|---|
| 预筛打分、事件卡、英文网页稿 | MiMo（flash） | 快、便宜，有逐字核对兜底 |
| 选题终审 | MiMo 初选，Claude 复核 | 两边一半不同，复核能补盲点 |
| 播客稿、中文网页稿 | Claude 主笔 | "讲新闻"明显更好 |
| 视频稿 | Claude | 和播客错开角度 |
| 出错时 | 自动换另一家 | Claude 不可用就由 MiMo 写；都不可用就只发数据版 |

**Claude 能不能自动化**：能，两条路都是官方支持的。

- **A. 用你的 Max 订阅**：本机运行一次 `claude setup-token`，把生成的令牌存进 GitHub 的密钥。和你平时用 Claude Code 共用额度，每天写一期约十几分钟，影响不大。
- **B. 用每期 $100 的 API 额度**：Console 建一把密钥。按精简后的输入估算，用 Sonnet 5.5 每月约 $5–8，用 Opus 5.5 约 $10–15。

建议先用 A，额度紧张时切到 B。两个不要同时配：同时配时会默认扣 API 的钱。

### 4. 在哪儿每天跑

| 方案 | 优点 | 缺点 |
|---|---|---|
| GitHub Actions（云端） | 不靠家里电脑；期刊监控就是这么跑的 | Codex 生图在云端不好用（可改用 Gemini 生图，每张约 $0.03） |
| Mac mini 本机定时 | 所有订阅都已登录，Claude、Codex、MiMo、Gemini 全能直接用，几乎零额外花费 | mini 必须开机联网；家里断网那天就停 |
| 混合（建议） | mini 负责生成，GitHub 负责发布；mini 没交稿时，云端自动跑一个只用 MiMo 和 Gemini 的简版 | 搭起来多一两天 |
