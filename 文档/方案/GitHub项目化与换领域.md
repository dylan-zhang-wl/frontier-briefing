# 做成一个能搬走、能换领域的 GitHub 项目

2026-11-01 14:40 写。接 `文档/方案/改版计划_v3.md` 第十三节（打包成 skill），把用户 11-01 下午提的要求落成方案：

> 后续要能完整生成一个 GitHub 项目：换电脑或换会员订阅后，任何 agent 都能一步步指导登录订阅、配置 API，完成配置；还能换成教育、纯学术等其他领域的每日（或改时间的）前沿资讯。

这份是方案，还没动手。动手放在第 6、9、10 批，见最后一节。

## 一、最后是什么样子

一个 GitHub 私有仓库就是全部：代码、配置、说明都在里面，成品不在里面。

- **换电脑**：把仓库下载到新电脑，打开任何一个 agent（Claude Code、Codex、Gemini），说一句"帮我把这个项目配好"。agent 读仓库里的总说明，先查这台电脑缺什么，再按顺序一项项带你装、带你登录。每一步都验一下通没通，通了才往下走。
- **换订阅**：比如 ChatGPT 不续了、Gemini 赠金用完了，就跟 agent 说一声。它改配置里的模型顺序，再验一遍备用的那条路通不通。
- **换领域**：说"我想做一份教育前沿的每日简报"。agent 复制一份配置档，带你走一遍：定读者、选来源、定选题规则、试写一期、你改、选声音和配色、试跑、上线。

agent 只看密钥有没有、能不能用，不看密钥的内容。密钥由你本人在隐藏输入框里填，或者存进钥匙串（macOS 自带的密码保险箱）、GitHub 的 Secrets（仓库里专门放密钥的地方，填进去后谁都看不到原文）。

## 二、仓库怎么分

核心是把**引擎**和**配置档**分开：
- 引擎是代码，只有一份；
- 配置档是一份简报的全部个性，换领域就是换配置档。

```
frontier-briefing/                仓库名待定
├── README.md                     给人看：是什么、长什么样、从哪开始
├── AGENTS.md                     给任何 agent 的总入口（CLAUDE.md、GEMINI.md 只写一行"先读 AGENTS.md"）
├── docs/
│   ├── setup/                    分步配置，一个账号一页
│   ├── lessons/                  经验库：问题与解决办法、检查清单（现在的 文档/经验/）
│   └── design/                   方案文档（现在的 文档/方案/）
├── engine/                       引擎：现在的 pipeline/、site/tools/、site/v3/
├── profiles/
│   ├── ai-tech/                  现在这份"每日AI科技前沿简报"
│   └── _template/                新领域从这里复制
├── fd                            一个命令入口（见第四节）
├── .github/workflows/            云端定时运行
└── tests/
```

- **文件夹名用英文**：命令行好打，云端也不出编码问题。文件内容照旧用中文，提示词、说明都不用翻。现在的 `pipeline/`、`site/` 迁过去时一起改名，改完要跑一遍全部测试。
- **成品不进仓库**：
  - 每期的网页、音频、视频发布到 Cloudflare（R2 存文件、Pages 放网页）；
  - 本机另放一份在仓库外，路径写进配置；
  - 这样仓库一直很小，搬起来快。

## 三、配置档里有什么

一份简报一个文件夹，主文件是 `profile.yaml`，其余是它引用的提示词、来源清单、读音表等。

| 类别 | 内容 | 现在在哪 |
|---|---|---|
| 名称与读者 | 中英文名、简称、语言、读者是谁、口吻（只说"我们"） | 散在 `v3_site.py`、写作指南 |
| 时间 | 时区、出刊时间、抓取窗口（开跑前 36 小时）、一周节奏（哪几天日常版、哪天深谈版） | 代码里写死 |
| 来源 | 来源清单、权重、专业雷达来源 | `pipeline/sources_test.yaml` |
| 选题 | 主线 2–3 条、各栏目条数区间、中外比例、同一家公司上限、意外度、专业雷达关键词 | `prompts/选题.md` |
| 写作 | 写作指南，播客、网页、视频各自的提示词，读音表，英文名表 | `pipeline/prompts/` |
| 成品 | 要哪几样（网页、播客、视频），播客时长区间，视频不超过 3 分钟 | 散在代码 |
| 声音 | 主播、周日搭档，各自的声音 ID、参考音高、响度、语速；声音包和署名 | `voice_profile.json`、`assets/music/` |
| 视觉 | 主题色规则、字体 | `site/v3/` |
| 模型 | 每个环节用什么、坏了换什么、每月花费上限 | 散在代码 |
| 发布 | 网址、隐藏期、存档 | 还没有 |
| 把关 | 哪些检查必须过；先审后发，还是自动发 | 11-08 定：审片没发现问题自动发（审片结论 `审片结论.json`）；配置档还没有 |

**拿两个新领域试想一下**，看配置档够不够用：

| | AI 科技（现在） | 教育前沿 | 翻译与语言学术前沿 |
|---|---|---|---|
| 来源 | 科技媒体、公司博客、社交平台 | 教育部和各地教育部门、教育媒体、国际教育组织、高校新闻 | 期刊 RSS（可直接接期刊监控的数据）、arXiv 计算语言学、学会通知、征稿 |
| 节奏 | 每日 | 每日，或一周三期 | 一周一期更合适，论文更新慢，每天会很薄 |
| 选题看什么 | 热度、主线、意外度 | 政策影响面、落地时间、和一线教学的关系 | 方法或发现新不新、对本领域研究者有没有用 |
| 核查 | 数字逐字对原文 | 同左，另加政策文号、生效日期 | 题名、作者、DOI 逐项对，不许编引用 |
| 成品 | 网页、播客、视频 | 网页、播客 | 网页为主，播客可选 |

三列的差别都落在配置档里，引擎不用改。只有学术那列的"DOI 核对"要在引擎里加一个检查，这个检查以后各领域都能用。

## 四、一个命令，四种用法

`fd` 是仓库根目录的一个小程序，agent 和人都通过它操作：

| 命令 | 做什么 |
|---|---|
| `fd doctor` | 体检：软件装没装、各账号登没登、密钥在不在、各条备用路通不通。每项给"好了／缺了／怎么补"。只查不改，不显示密钥 |
| `fd setup` | 按顺序带着配：每一步说清做什么、为什么、要不要钱，等你在网页上点完登录，再自己验证一遍。进度记在 `setup_state.json`（不含密钥），换个 agent 或明天接着做都能续上 |
| `fd run --profile ai-tech --date 2026-11-02` | 跑一期，从抓取到组装；`--until 写稿` 只跑到某一步 |
| `fd new-profile 教育前沿` | 从模板复制一份配置档，再进入问答式配置 |

## 五、要开通的账号，一页一个

`docs/setup/` 里每个账号写一页，格式相同：
- 做什么用；
- 是不是必需的；
- 要不要钱；
- 怎么开通；
- 本机的密钥放哪；
- 云端的密钥放哪；
- `fd doctor` 怎么验。

| 账号 | 做什么用 | 必需 | 本机 | 云端 |
|---|---|---|---|---|
| GitHub | 放仓库、每天定时运行 | 是 | 登录 `gh` | — |
| Claude 订阅 | 选题、写稿、审读 | 是（主笔） | 登录 Claude Code | 本机运行一次 `claude setup-token`，生成的长期令牌由你填进 Secrets |
| Claude API | 订阅用完时的备用主笔 | 否 | 钥匙串 | Secrets |
| Google Cloud | Gemini 配音、声音设计 | 是（主配音） | `gcloud` 登录 | 用"免密钥授权"（Workload Identity，让 GitHub 凭身份直接调用，不存长期密钥） |
| 小米 MiMo | 事件卡、备用配音 | 是 | `.env` 或钥匙串 | Secrets |
| ChatGPT 订阅 | 生图 | 否，没有就用程序画的封面 | 登录 Codex | 登录凭证加密存进 Secrets；OpenAI 要求仓库必须私有 |
| Cloudflare | 发布网页、存音频和记录 | 上线时必需 | — | Secrets |

**每一步都有闸口**，前一步验通了才往下走：

1. 体检；
2. 定主题和读者；
3. 逐个开通账号；
4. 选来源：先试抓一天；
5. 定选题规则；
6. 定写作口吻：试写一期，你改；
7. 选声音：盲听；
8. 定视觉：出样张；
9. 本机试跑一期；
10. 上线：先用不公开的网址跑一周；
11. 日常维护。

这和第十三节原来的九步一致，只是把"开通账号"拆细了。

**怎么验收"任何 agent 都能带着配"**：仓库做好以后，在一个干净的环境里从零走一遍，比如 Mac 上新建一个用户，或者云端的一台空电脑。分别让 Codex 和 Gemini 只凭 `AGENTS.md` 带着走，哪一步卡住就改哪一步的说明。

## 六、出刊时间可以改

- 配置档写本地时区和本地时间，比如"Europe/London 05:00"。云端的定时只认世界标准时间，所以程序开头先看一眼"现在是不是配置里的本地时间"，不是就退出。定时任务每天在两个候选时刻各触发一次，冬令时、夏令时都能对上。
- 要先想清楚**读者在哪个时区**。读者在国内、想早上听，北京时间 7 点出刊是英国的 23 点或 0 点，抓取窗口要跟着挪。这件事上线前要你定。

## 七、你让我想的"还有什么要注意"

只列和这个项目真有关系的，按要紧程度排。

1. **把关放在花钱之前。**
   - 这次最大的教训：独立审读放在配音之后，改了稿只好重配。以后的顺序是：写稿 → 数字核对 → 独立审读 → 改稿 → 配音 → 配音后查音高、语速、时长 → 组装 → 网页检查。
   - 没过的处理按这个顺序：先重做一次，还不过就放宽，再不行换备用；实在不行只发"数据版"（网页文字，不带音频），同时发邮件告诉你。没过把关的东西不自动发布。
2. **上线头两周先审后发。** 每天生成到不公开的网址，你在手机上看一眼再放出去。两周没出事，再改成自动发布、只发通知。（11-08 改：不再先审后发，审片没发现问题就自动发布；不放行时网站不动、发邮件。）
3. **花费设上限。** 每期、每月各一个上限，到了 90% 就降级到便宜的备用并提醒你。做法和 Codex 桥接的预算闸门相同。
4. **模型版本固定，每期记下来。**
   - 声音和模型版本是绑在一起的：Gemini 一升级，同一个声音 ID 念出来可能就变了。
   - 所以每个声音存一段"定稿样音"和参考音高，每期配完自动比一下，明显漂了就提醒你。这次加的"音高把关"就是第一步。
5. **版权和署名。**
   - CC BY 的配乐必须署名，放在折叠的参考来源里；
   - 公司标志只用来指认是哪家公司，单色、不变形；
   - AI 配图不画真人和商标；
   - 引用原文要短，并给链接；
   - 早咖啡这类节目只学形式，不用内容，不拿去喂模型。
6. **新领域先看来源够不够。** 教育、学术的来源每天的量远少于 AI 科技。换领域时先试抓一周再定节奏，别默认每天出。
7. **多一份简报，就多一份用量。** 所有简报共用同一套订阅和额度。别人要长期用，最好用他们自己的账号。
8. **维护负担。** 每周一封小结邮件，内容是：
   - 花了多少；
   - 哪步出过错、怎么补救的；
   - 哪些来源一周没贡献。

   平时不用盯。
