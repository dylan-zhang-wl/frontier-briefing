# 深化设计：获取、选题、写稿

2026-10-31。回应你 10-30 晚的意见。方案讨论稿里与本文冲突的地方，以本文为准。

## 零、这次定下的事

1. **语言**：以中文为主，核心术语带英文。网页全页可以中英切换；播客先做中文，英文版放到以后。
2. **用已有的订阅和接口**：
   - 选题和写稿：MiMo 和 Claude 对比。本机没有 Claude API 密钥，所以先用 Claude Code 订阅额度。
   - 生图：Codex 订阅，已测通。
   - 配音：MiMo 和 Gemini 对比。Gemini 用的是你当时新换的另一个账号，已测通。
   - 视频：由 Claude Code 做。
3. **网页和播客形式不同**：
   - 网页：顶部"每天一张卡"，下面先放视频，再放图文。
   - 播客：10 分钟起步，沿用早咖啡式的仪式感。
4. **一周的节奏**：
   - 周一到周五："开场 → 热点 → 要闻 → 快讯 → 今日一词 → 结尾"；
   - 周六：一个话题的深度解读，时间更长；
   - 周日：双人问答。
5. **视频**：用 HTML 动画嵌在网页里，内容和当天同步，但讲法和播客不同。

## 一、获取：不全抓，盯住该盯的

### 1. 别的项目怎么获取（这次读了它们的代码和文档）

| 项目 | 获取策略 | X 怎么拿 |
|---|---|---|
| AIHOT | 信源分三级，各设不同门槛；先粗筛，再两次打分 | 付费的第三方接口 SocialData，按请求计费；公众号用付费服务"极致了" |
| Horizon | 用"兴趣档案"定义关注什么；十类信源 | 付费的第三方爬取平台 Apify，或者用浏览器模拟登录去抓 |
| AINews | 固定名单：几百个 X 账号、十几个 Reddit 版块 | X 官方接口加人工 |
| BestBlogs | 7 个接口约 700 条候选，每天只选 10 条 | 不接 |
| follow-builders | 只盯一份精选的"建造者"名单 | 作者维护一个公共订阅源 |

**结论**：成熟项目都不是"全抓"，而是"名单加门槛"。X 上的帖子没有一家能免费拿到：要么用付费的第三方抓取（违反 X 条款），要么用官方付费接口。

### 2. 负责人在社交媒体上的发帖和预告：免费能做到什么

下面四条叠着用：

1. **AINews 的"X 回顾"和"Reddit 回顾"**：它每天看几百个 AI 账号，免费。程序把回顾拆成一条条"社交信号"：谁、说了什么、原帖链接。
2. **媒体对预告的报道**：量子位、新智元、The Verge 等常写"某某深夜发帖暗示……"，这些订阅源都免费。
3. **其他平台的同步发布**：
   - Bluesky、Mastodon 有免费的订阅源，不少研究者在上面发帖；
   - 公司和负责人的 YouTube 频道、播客也有免费订阅源，访谈里常透露计划。
4. **你自己的书签**：刷 X 时顺手加书签，程序只读你的书签。X 官方按条收费 $0.001，首次充值送 $20；按每天 30 条算，够用一年半以上。严格说不算免费，但几乎不花钱，而且完全合规。

**预告怎么处理**：
- 单独放"预告观察"栏，标"未经证实"；
- 写清楚谁、在哪、原话大意，以及几种可能的解读；
- 自动进入追踪清单，以后兑现或落空都回头交代一句。这就是你要的"互文"。

### 3. 中国与国际：两条线，一张网

- **国际线**：实验室官方渠道；国际科技与商业媒体，包括早咖啡常引用的华尔街日报、彭博、金融时报、路透、The Information（见第 5 小节）。
- **中国线**：
  - 国内大模型公司的官方渠道：Hugging Face 和 GitHub 上的发布记录、官方博客；
  - 中文科技与财经媒体：36氪、量子位、新智元、IT之家、极客公园等。
- **怎么关联**：用一个懂中英文的句向量模型（LaBSE，本机已有，免费），把中英文报道放进同一个"意思空间"：
  - 同一件事的中英文报道自动合并；
  - 意思相近但不是同一件事的，标成"中外对照"候选，比如美国新模型降价，对照国内同类模型的价格。

### 4. 获取要过三道筛

1. **名单**：信源分级（A 每天必看，B 补充，C 备用），加一张关注实体表，列出公司、模型、人物、产品、政策。
2. **粗筛**：用关键词和实体匹配，不调大模型，几乎不花钱。
3. **先归并，再打分**：先把同一件事合并成事件，再交给大模型打分。这样调用次数从上千次降到几十次。

### 5. 早咖啡引用了哪些信源

做法：在本机转写了 5 期新闻串讲（10-12 至 10-28），统计口播里"根据某某某日的报道""某某认为"提到的出处。转写音频和文字统计完就删了，只留下出处名单。Whisper 会把专名转错（"36氪"成了"36克"，"Axios"成了"Exos"），已人工合并。

| 出处 | 5 期里约被引用几次 | 我们能不能免费拿到 |
|---|---|---|
| 彭博社 | 14 | 有科技频道订阅源，正文多在付费墙后，取标题和摘要 |
| 财新 | 12 | 没有官方订阅源；RSSHub 有路由，要自建 |
| 界面新闻 | 10 | 同上 |
| 路透社 | 7 | 官方订阅源已停；可以用新闻检索接口找标题 |
| 《财经》杂志 | 7 | 同财新 |
| 第一财经、日经 | 各 4 | 第一财经同财新；日经有英文订阅源 |
| 36氪 | 4 | 有订阅源，已接入 |
| 晚点、金融时报 | 各 3 | 晚点只在公众号和官网；金融时报有订阅源，正文付费 |
| 华尔街日报、The Information、TechCrunch、纽约时报、Axios、澎湃 | 各 1–2 | 多数有订阅源，取标题和摘要 |
| 研究机构：QuestMobile、Counterpoint、胡润研究院 | 各 1 | 报告发布页，按需引用 |

**结论**：早咖啡的底子是"国际通讯社和财经媒体，加国内财经媒体"。国际这一半，订阅源加新闻检索接口基本能覆盖。国内财经媒体（财新、界面、《财经》、第一财经、澎湃）大多没有官方订阅源，第二期要自建 RSSHub（一个把网站转成订阅源的开源程序）来补；能不能稳定抓到，要实测。

## 二、选题：今天讲什么

### 1. 六个评分维度（借鉴 AIHOT 和 Horizon，按你的需要改过）

| 维度 | 看什么 |
|---|---|
| 重要性 | 对行业、对普通用户有多大影响 |
| 可信度 | 有没有一手来源，有几个独立来源 |
| 新鲜度 | 是不是第一次出现，往期讲过没有 |
| 关联度 | 有没有中外对照，能不能接上往期 |
| 贴合度 | AI 为主；与语言、翻译、教育相关的加分 |
| 可讲性 | 有没有数字、对比、人物、故事 |

### 2. 版面配额（工作日）

- 2 条热点（深讲）、4 条要闻、5–8 条快讯。
- 与中国相关的至少占三成；同一家公司不超过 2 条；至少 1 组中外对照。
- 预告观察 0–2 条，不算正式新闻。
- 同一套标准，MiMo 和 Claude 各打一遍分；两边不一致的条目重点看。

### 3. 一周节奏

| 日子 | 形式 | 时长 | 怎么选题 |
|---|---|---|---|
| 周一到周五 | 开场 → 热点 → 要闻 → 快讯 → 今日一词 → 结尾 | 10–12 分钟 | 当天打分加配额 |
| 周六 | 一个话题的深度解读：发生了什么 → 来龙去脉 → 各方怎么说 → 中外对照 → 还不确定什么 | 15–20 分钟 | 从本周的"周末深度候选"里选，或者选你在工作台上标了"想深挖"的 |
| 周日 | 双人问答：一人代表听众提问，一人解答；回顾本周三四个话题，加上预告的兑现情况 | 12–15 分钟 | 本周热点加追踪清单 |

早咖啡自己是周一到周五更新：周一、周三是"轻解读加快讯"，周二、周四是新闻串讲，周五是"咖啡豆"（回答听众提问的深度话题）。周末不更新。你的节奏补上了周末，正好和它错开。

## 三、写稿：从"念新闻"到"讲新闻"

### 1. 三种成品各有分工

| | 网页（日卡加图文） | 播客 | 视频（网页内的 HTML 动画） |
|---|---|---|---|
| 目的 | 快速扫读，方便查证 | 通勤时陪着听，听懂来龙去脉 | 看懂一两件最重要的事 |
| 长度 | 日卡三行；图文逐条展开 | 10 分钟起 | 70–100 秒 |
| 讲法 | 结构化，数字和来源最全 | 口语，有串联，早咖啡式的仪式感 | 画面为主，字少，多用对比图 |
| 中英 | 全页切换 | 中文（英文版以后再做） | 画面文字可切换 |

### 2. 联动、互文、生动：一半在选题，一半在写稿

你问这是不是写稿时要注意的事。是，但只靠写稿做不到：写稿的人手里得先有"关系"可串。所以：

- **选题阶段**：给事件卡加"关联"字段，写明同期哪两条是中外对照、和往期哪一期有关、对应哪条预告。这一步靠句向量找相近事件，再加大模型判断。
- **写稿阶段**：用《写作指南》里的写法把关系讲出来。

| 手法 | 做法 |
|---|---|
| 联动（同一期内） | 条目之间用一句话接上；有中外对照的两件事放在一起讲 |
| 互文（跨期） | 回扣往期，"之前说过……今天有了下文"；交代预告兑现了还是落空了；系列话题沿用固定叫法 |
| 引语 | 用一两句当事人原话，网页上中英对照 |
| 生动 | 数字带比较，换成能感受到的说法；先给结论再展开；句子长短交替；偶尔向听众提问 |
| 不写 | 夸张词（"炸裂""碾压"）、没有出处的判断、把预告当事实 |

要做到"互文"，系统得记得以前讲过什么：每期的事件卡都存档，写稿前按相似度取回相关的往期条目，一起交给写稿模型。测试版只有一期，暂时体现不出来；正式运行一周以后才会明显。

### 3. 中英文怎么处理

- 中文正文里，核心术语第一次出现写成"中文（English）"，之后只用中文；人名、公司名、模型名保留原名。
- 网页英文版根据同一份事件卡重新写，不逐句翻译中文。
- 播客里英文专名按英文读，必要时补一句中文解释。

### 4. 防止写错

- 事件卡里每个事实、每个数字，都附原文里的逐字片段。程序检查这个片段在原文里找不找得到，数字在不在片段里。
- 写稿模型只能用事件卡里的事实。"为什么重要"属于解读，要和事实分开写，并写明是谁的判断。

## 四、这次测试验证什么

1. **获取**：约 50 个信源、两天的真实数据；粗筛、跨中英文归并、中外对照候选。
2. **选题**：同一份候选，MiMo 和 Claude 各选一遍，对比两份结果。
3. **事件卡**：抽取事实，再逐字核对出处。
4. **写稿**：同一份事件卡，MiMo 和 Claude 各写一版播客稿；网页稿和视频稿也各写一版。
5. **配音**：同一份播客稿，分别用 MiMo 和 Gemini 配整集；另有 6 段测试稿样音供盲听。
6. **成品**：本地网页，包括日卡、HTML 动画视频、播客播放器、中英文图文；配图用 Codex 生成。
