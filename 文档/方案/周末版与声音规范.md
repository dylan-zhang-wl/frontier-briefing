**时长由程序把关**，做法和视频的 3 分钟一样：
- 配音前按字数估，超出区间就退回写稿，不配音；
- 配完按实际时长再查一遍；
- 字数和时长的换算按每个声音实测的语速算，每次换声音后重测。现在的估法是：日常版每分钟约 240 字（2,800–3,300 字对应 12–13 分钟），对谈要等第一期周日稿出来再测。

| 段 | 时长 | 内容 |
|---|---|---|

| 快讯 | 3–4 分钟 | 5–6 条：周五到周六的新消息为主，每条照旧报日期和来源 |
| （转场声） | | 全集只放这一次 |
| 深度一题 | 6–7 分钟 | 三层讲透：发生了什么、为什么重要（怎么运作、关键数字怎么读）、接下来看什么。结尾落一句"我们的理解" |
| 结尾 | 约 30 秒 | 收一句，留一个生活化的问题 |

## 三、周日：双人深谈

一件事讲深：过去一周反复出现、不久还会有影响的热点，再把相关的事串起来讲。不是一问一答，不是回顾一周，也不是兑现预告。

**结构**：

| 段 | 时长 | 谁说 | 内容 |
|---|---|---|---|
| 开场 | 约 1 分钟 | 两人 | Shirley 问候、报日期、介绍 Dylan；Dylan 打个招呼，抛出这期的核心问题 |
| 本周快讯 | 约 3 分钟 | Shirley 为主 | 3–4 条，不和深谈重复；11-14 起周六不出刊，周五、周六两天的新消息都由这一块覆盖（11-08 定）；Dylan 可以插一两句，让他一开始就在场，后面就不是突然加入 |
| （转场声） | | | 全集只放这一次 |
| 深谈 | 10–12 分钟 | 两人 | 五层，见下 |
| 结尾 | 约 1 分钟 | 两人 | 回到开头的问题：确定到哪一步、还不确定什么；点一两个接下来要盯的节点；最后留一个生活化的问题 |

**深谈五层**，拿你举的例子说明。假设周一 Anthropic 发布了 Fable 5.5，这一周各行业的消息都在讲它能写作、写代码、做 3D、做视频、跑大型工程：
1. **来龙去脉**：这一周它在各行业的几个节点；它从哪来，和上一代 5.1、和 Opus 5.5 比变了什么。
2. **为什么这么好**：技术上公开了什么，怎么训练的；没公开的就说"官方没公开"，不替它猜。
3. **关键数字怎么读**：价格、算力、评测分数，各自的口径是什么。
4. **各方怎么看**：官方说法对照第三方评测，质的提升在哪、保留意见在哪；再串上竞品的回应、国内的对应产品，这就是"互文"的部分。
5. **对工作和生活意味着什么**：我们的看法，用"如果……就说明……"讲接下来要盯什么。

**分工**：按层面分，不按"一个问、一个答"分。
- Shirley 推进节奏，主讲商业和社会层面：谁付钱、谁受影响、跟普通人有什么关系；
- Dylan 主讲技术和证据层面：东西怎么运作、数字什么口径、评测有哪些保留；
- 每层由负责的人主讲，另一个人替听众追问，或者补一条反面材料。分歧只来自不同来源的不同说法，不为热闹制造对立。

**选题四条标准**：
1. 这一周至少三天出现在我们的热点、要闻或追踪清单里；
2. 未来一到四周有一个看得见的节点；
3. 材料够撑五层；
4. 有一个反差能做开头。

**选题流程**：
- 给出两三个候选，各附一句理由，默认用第一个，全自动往下做，不等你看（11-08 改：原为"周六晚给出两三个候选……上线头几周你看一眼再定"；11-08 定审片没发现问题就自动发布）。周六照常抓取、入库，候选照样能排出来。
- **前提是往期事件库**：每天讲过的事存下来，周末才能汇总一周。

## 五、声音规范

### 1. 声音身份固定，语气按内容变

- **"语气"是什么**：每次合成时，告诉配音模型"怎么说"的那句话，管情绪、轻重、快慢。它不直接管音高，但会带动音高：写了"明亮、有活力"，Gemini 就会把嗓子提上去，听着像换了个人。10-31 的工作日稿和 11-01 的视频开场都是这样。
- **改成两层**：
  - 固定层：声音 ID 加上"音区抬高"那句，再加一句基础语气，定死这是谁。
  - 变化层：每章从一张"情绪色板"里选一个词，由写稿的模型按内容选。比如裁员、事故用"沉稳、关切"，轻松的产品新闻用"轻松、带点笑意"，复杂的技术用"放慢、清楚"。
- **色板要先测**：拿同一段话，每个候选词各配两次，量音高、音色、语速。只留下音高偏移不超过 1 个半音、音色不跑的词。约花 $0.04。
- **兜底**：音高、音色两道把关照旧在后面拦着。
- 工作日播客、周六、周日、视频都用同一张色板。

### 2. 音量

**已经自动化的**：
- 每块、每章都统一到 −16 LUFS，这是播客常用的标准响度；视频成片也是 −16 LUFS；
- 对谈里 Dylan 比 Shirley 低 0.7 LU，程序会量、会校。

**这次要加的：句子级找平。**
- 每块、每轮里，把明显比左右响或轻的整句拉回来：偏离超过 1.5 LU 才动，只动音量、不压缩，保留正常的轻重；
- 不花钱，全自动。

### 3. 语速

**现在有的**：
- Gemini 靠语气里的"保持同样的语速"来管；
- MiMo 不听语速提示，靠后期变速；
- 程序会量，和参考差一成以上只标出来。

**要不要一致**：同一个人每天的平均语速应该稳定，听众才觉得"还是她"；一章之内随内容快慢变，是正常的。所以只修偏离太多的：

| 一块或一轮离参考 | 怎么处理 |
|---|---|
| 6% 以内 | 不动 |
| 6–12% | 后期微调速度，不改音高，最多调 8%，耳朵听不出 |
| 超过 12% | 重录 |

- 选了"放慢、清楚"这类情绪的章，参考语速跟着放宽。
- 对谈里两人差不超过 5%。
- Shirley、Dylan 用同一套规则。

### 4. 备用声音（MiMo）

- **MiMo 有没有固定声纹**：没有声音 ID，参考录音本身就是"声纹"。每次合成都照着同一条录音去学，所以音色其实比 Gemini 还稳：06 五次合成之间 0.91，庚A 是 0.74–0.77。
- **它的问题是偶尔失控**，比如多念一大段、拖成两倍长。现在有对稿、时长、音高、音色四道拦着。
- **参考录音在项目里**（`pipeline/assets/voices/`），换电脑也能原样用。
- **改进（用户 11-01 晚同意试）**：现在的备用是另外两个人（乙稍快、06），Gemini 出错那天，听众会听到别的主播。试一下用 Shirley、Dylan 自己的定稿录音做 MiMo 复刻。如果音色指纹和原声足够近、耳朵听也像，备用那天就还是 Shirley 和 Dylan。MiMo 现在免费，试一下不花钱。

### 5. 视频只用 Shirley

视频旁白每天都只用 Shirley，现在就是这样；Dylan 只出现在周日播客里。

## 八、出刊时间和时区

- **目标**：早上 7 点左右能看到。整条流程从抓取到组装，自动化以后估计 30–45 分钟，加上重录和补救的余量，在当地 5:30–6:00 开跑。
- **年底回国以后按北京时间**：时区和出刊时间写在配置里，改一行就行，不改程序。要跟着时区一起变的有三样：
  - 抓取窗口；
  - 稿子里报的日期和星期几；
  - 当天出哪一版（日常、周六、周日），都按北京的日期算。
- **注意时差**：北京时间早上 7 点是美国西部前一天下午三四点，美国那边当天的消息大多已经出来了。这对国内早上的读者正合适。
- **到时候顺带查一件事**：云端服务器在国外，按北京时间定时没有问题，但要在国内网络下实际打开一次网页和音频，看看能不能正常访问。
